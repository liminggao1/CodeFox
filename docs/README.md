# 文档索引

`docs/` 保存项目级设计与执行记录。代码细节紧邻代码或测试，个人操作笔记放 `note/`，不在这里重复。
领域术语见 [GLOSSARY.md](../GLOSSARY.md)，运行方式和代码布局见 [README.md](../README.md)。
具体模块职责和调用关系见 [源码结构说明](../src/agent_harness/README.md)，各子包维护自己的文件分工。

Git 历史按功能里程碑整理。已实施的事实写在 [仓库事实](facts.md)，不再按计划拆分记录；提交号与中间过程由 Git 历史保留，不在文档中重复。

`plans/` 放计划类文档：功能开发计划、路线、待验证与待决策等。已全部实施且无遗留的计划把事实并入 `facts.md` 后删除；一条规则全项目只有一个权威来源，读的人不需要在矛盾说法间判断。

项目面向可长期演进的本地 agent 运行环境，保留主循环、工具、子 agent、工作流和目标控制的完整机制。
项目当前不做打包发布。
当前验证包括离线模型驱动的持久子 agent、跨任务目录与历史、通信和关闭，以及两种子 agent 模式的端到端自检；真实 API 交互问答和 memory 抽取尚未实测，未验证边界见 [待验证事项](plans/2026-10-11-01待验证事项.md)。

## 命名规则

- 架构决策用 `adr/<四位序号>-<短名称>.md`，序号从 `0001` 起。
- 计划用 `<日期>-<两位顺序号><目标名称>.md`，同日序号从 `01` 起，按首次实施顺序排列；分阶段续做保留原编号。
- 交接用 `<日期>-<主题>-handoff.md`，放在 `handoff/`。
