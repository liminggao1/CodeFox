# 仓库事实

本文记录 agent-harness 当前生效的架构与行为事实，按仓库演进里程碑组织。
只描述当前状态，不记录规划过程、实施顺序与当时的测试数；历史决策由 Git 保留。

权威分工：运行方式与代码布局见 [README.md](../../README.md)，术语见 [GLOSSARY.md](../../GLOSSARY.md)，
文件分工见 [源码结构说明](../../src/agent_harness/README.md) 与各子包 README，本机环境见 [AGENTS.md](../../AGENTS.md)。
本文只维护跨模块的架构与行为规则；同一事实不在两处并列，本文与上述文件冲突时以代码为准。

## 1. 结构初始化（2026-10-04）

项目由 s15 集成宿主、s16 workflow 运行时与 s17 goal 循环合并而来，现为自有的本地 code agent
运行环境；不打包发布，不做多运行时实例隔离。

- 布局为 `src/agent_harness/`，console 入口 `agent-harness` 与 `python -m agent_harness`；包内用相对导入。
- 资产随包分发：`skills/` 位于包内，`SKILLS_DIR = PACKAGE_DIR / "skills"`，editable 与 wheel 安装都能解析。
- 任务、记忆、工作流、后台任务等运行时状态跟随**当前会话的启动目录**：`.tasks`、`.memory`、
  `.mailboxes`、`.worktrees`、`.runtime`、`.scheduled_tasks.json` 与 `.task_outputs`；交互会话上下文、
  会话诊断、压缩归档及长工具输出存放在 `~/.agent-harness/sessions/` 下并随会话删除。
- `.env` 由 `load_dotenv()` 从包文件位置逐级向上查找，与启动目录无关。
- memory 以正常导入接入并共享 client / model / workspace，不再按路径 `importlib` 加载。
- workflow 直接进入工具池；`run_workflow_sync` 用 `asyncio.run` 桥接同步宿主与异步运行时。
- goal 接在 Stop 边界：模型不再请求工具时先问 `GoalController`，`block` 则补 `[Goal still active]` 继续；
  goal 状态只存在内存，默认 `block_cap=8`、`MAX_GOAL_LENGTH=4000`。
- 跨平台：`fcntl` 用 try/except 包裹，无 fcntl 时退化为进程内锁并打印一次提示。
- 文档骨架：`docs/{adr,plans,research,handoff,guides,agents}/`、`note/`、`.scratch/`（本地议题）、`tmp/`（本地临时，不入库）。

## 2. 架构调整（2026-10-06）

目标是减少定位一次工具调用、任务分配和恢复流程时跨越的模块数，并明确可变状态的所有者。

- 任务归属三分：`workspace/tasks.py` 负责任务持久化、认领、assignment 与目录查询；
  `workspace/worktrees.py` 只负责 Git 与目录；`workspace/task_worktrees.py` 负责两者的绑定与移除
  （含占用检查、跨进程任务锁、部分成功后的报错）。
- 依赖方向为 `agents` / `tools` → `workspace.tasks` → `workspace.worktrees`；`worktrees` 不反向导入任务。
- 启动目录、配置、client 与 CLI 状态由 `core.py` 持有；任务、memory、workflow、transcript 与工具结果
  在调用时读取当前目录，`host` 不再维护 client 副本。提示词快照与动态状态见第 10 节。
- workflow journal 记录每次新调用及累计 token 用量；相同 `prompt/label/schema` 的并发调用只执行一次；
  缺 `tokens` 的旧格式记录在 resume 时明确报错（旧文件保留，重跑生成新格式）。
- cron：循环 cron 仅在本进程内按分钟去重，重启后同一分钟可再次触发；持久化的一次性任务采用至少一次交付
  （入队前落盘，模型调用被接受后才确认，确认前崩溃允许重投）。
- 调度器独占后台任务、cron 队列与锁。调用方只查询待交付状态或进入操作作用域；会话激活前重新检查 cron，
  检查到激活完成期间阻止新任务入队；工作树移除从后台占用检查到目录移除与任务解绑保持同一互斥范围。
- Lead 与子 agent 共用完整执行循环；各自的工具集合、预算、停止与恢复策略保持独立，循环职责见第 8 节。

## 3. 两轮架构深化（2026-10-08）

第一轮把浅 module 加深，第二轮修正协议与恢复行为。当前事实：

- `context/memory_runtime.py` 只保留记忆能力（存储、索引、检索、抽取、整理）；旧 Agent runtime 已删除。
- `runtime_context.py` 以 frozen dataclass 和 tuple 持有上下文值，`build_context(messages)` 是唯一构造入口；
  Lead 在准备新请求时刷新，重试复用已准备的请求；CLI 与后台循环不持有共享 context。
- `tools/tool_registry.py` 统一装配工具 schema、handler 与 policy 快照，来源由宿主显式接线；
  `ToolDefinition` 是内置工具的权威目录；MCP 只提供动态定义。
- `agents/subagent_session.py` 的 `SubagentSession` 拥有工具 schema、cwd 绑定、hooks、工作预算与恢复策略；
  目录在工具调用时查询当前 assignment，不保存会过期的任务目录。
- `workflows/workflow_runtime.py` 与 `workflows/workflow_demo.py` 分离：核心拥有 runner interface、journal、
  预算、恢复、并发与工具入口；示例拥有 schema、样例编排、`DemoModelClient` 与 demo CLI。
- host 聚合重导出已删除，仓库调用方、测试和调试脚本直接导入真实职责 module，不再经 host 别名。
- Provider 保证交付的响应可消费：非法 JSON、顶层非对象、缺失调用身份与截断的工具批次都不转成正常结果，
  统一抛 `ProtocolResponseError`，不自动补括号、字段或参数值。
- `context/compaction.py` 的 `prepare_history` 拥有完整分层策略（瘦身、裁剪、摘要、手动/自动压缩、被动恢复）；
  自动、手动与被动入口都用 deepcopy 候选历史和切片提交，返回只读 `CompactionResult`。
- 后台结果领取先保存所有超过 200 字符的全文到 `.task_outputs/tool-results/background/`，再生成通知，
  最后移除整批记录；长通知包含全文路径，已保存路径在重试时复用。
- `agents/recovery.py` 的 `RecoveryState` 提供只读模型/额度/计数和固定转换方法，集中 Lead 的重试与恢复状态；
  429 与成功调用都打断连续 529 计数。

## 4. 统一子 agent（2026-10-14）

一次性子代理与持久实例统一称为**子 agent**，由模型通过运行模式选择生命周期。

- 创建入口唯一：`spawn_subagent(name, prompt, mode, description=...)`；短任务描述必填，
  `mode` 必须显式为 `once` 或 `persistent`。创建时生成稳定 `agent_id`，名称仍是可读别名。
  身份和结果只保留在当前进程内，不恢复线程、不新增会话持久化字段；展示事件仍随 Lead 会话保存。
- `once` 在工具调用内同步等待；`persistent` 登记并启动线程后立即返回 `started`，
  完成、失败、停止、预算耗尽和网络错误随后通过信箱通知。模式在创建时固定，存活期间不变。
- 已创建实例的返回值、终态通知和查询使用同一结果结构：`agent_id` / `name` / `description` /
  `role` / `mode` / `status` / `text` / `error` / `reason`、两种预算的计数与上限，以及 `usage`。
  usage 包含累计 `model_calls`、`input_tokens`、`output_tokens` 和总 `tokens`；校验失败不创建身份。
- `agents/subagent.py` 拥有创建、生命周期、活跃登记、进程内结果、信箱与协议投递；
  `SubagentSession.run(messages, before_iteration=..., before_complete=...)` 通过第 8 节的共享循环执行完整委派并返回最终响应。
  persistent 每轮准备前接收工作消息，检查预算后等待计划审批，恢复后再次检查；空闲等待留在生命周期外层。
- persistent 接受最终回答前会再收一次信：完成边界前到达的消息写入当前历史并续用当前预算，边界后到达的消息排入下一项工作。
  结果只在整个当前工作结束后通知一次；下一项工作启动时才重置工作预算。
- 管理工具：`list_subagents`、`get_subagent_output`、`send_message`、`request_shutdown`、`request_plan`、`review_plan`、
  `remove_worktree`（仅 Lead）。任何子 agent 都不提供 `spawn_subagent`、依赖修改或 worktree 创建/移除，
  保持不可递归。
- 通信由发送方模型决定；运行时只负责投递、唤醒和状态通知。执行结果、失败、IDLE 与关闭确认仍由运行时通知。
- 不使用任务板时用 `send_message` 委派下一次工作；使用任务板时 Lead 发任务 ID，子模型先 `claim_task(task_id)`
  再执行。子模型可调用 `list_tasks` 决定是否认领；每个实例同时最多占用一个任务。
- 已移除空闲线程定时扫描自动认领第一个任务的行为。
- 目录规则：有有效分配时用任务目录，无分配时用启动目录，分配失效时报错；任务状态与目录租约只由 tasks 管理。
- 工具能力：两种模式默认共用 bash、读、写、编辑、glob；`persistent` 追加 `send_message` / `submit_plan`
  和任务管理工具；`once` 显式分配 Task 后增加任务工具。省略 `tools` 使用默认集合，显式白名单只保留
  所选工具，`[]` 无工具。`shared_tools.child_tool_definitions` 是定义、处理器、描述、白名单及能力提示的统一来源。
  子 agent 提示只描述实际可用工具，不拼入 Lead 的通用工具提示；`read_file` 明示从 0 开始的 offset 和 limit。
- 每个工作单元默认最多 12 次模型请求、40 次工具调用，创建时可传正整数 `max_rounds` / `max_tool_calls`。
  模型预算包含上下文摘要请求；工具预算包含拒绝、未知工具和失败尝试，预算外调用只补 stopped 结果。
  进入计划审批等待前也检查预算；耗尽直接返回 `budget_exhausted`、部分结果和计数，不额外请求总结。
  部分结果取最新模型正文；本轮无正文时使用最新工具批次，不沿用早期证据。整批调用被停止或 Hook 抛错也补齐结果。
  once 结束并清理分配；persistent 耗尽后汇报并进入 IDLE，收到新委派重置计数，保留历史和累计用量。
  审批回复只恢复仍在等待的工作；已耗尽的工作可更新计划门禁，但须收到新委派才重新执行。
  未完成 Task 仍等待指导，失败或关闭时释放分配；空闲不请求模型。
- `get_subagent_output(agent_id, block=True, timeout=30)` 可即时查看或等待当前工作的结果，最多等待 60 秒。
  超时保留实际状态并标记 `timed_out`；查询不请求模型、不消费信箱、不重复通知，不暴露消息历史。
  结果在实例清理后仍可按 ID 查询；空闲后的消息或计划请求成功投递时同步清除旧结果，状态变为 `pending`。
  阻塞查询等待新工作，投递失败保留旧结果；启动前排队的消息合并到同一委派。通信、关闭及计划协议统一解析名称或 ID。
  计划请求在接收时按当前分配版本更新门禁，旧工作收尾不会解除新工作的审批要求。
- 子 agent 的通用 `read_file` 在权限审批前拒绝会话内部 `tool-results` 归档，
  按当前任务目录解析相对路径并解析符号链接；提示改读原始文件行范围。Lead 的目录外权限规则保持原状。
  执行或摘要请求的连接失败独立返回 `network_error` 并回滚该次模型预算；不因摘要失败继续请求执行模型。
  本地文件或清理错误归入 `failed`。
- 状态事件和 `list_subagents` 带身份、预算、累计用量及最后终止原因，保留原 `name` / `mode` / `status` 字段。
  列表与状态事件共用无正文的结果快照。同步 once 随用户停止结束；persistent 使用既有关闭协议，
  不因 Lead 单轮停止而批量终止。
- 工作流的 agent 步骤（`ctx.agent`）通过同一入口执行 once 子 agent，默认开放五项基础工具；`tools=[]` 只处理文本。
- 上下文压缩复用 `compaction`；实例身份与历史列表对象保留，压缩后模型输入必须包含当前委派与当前有效任务。

## 5. 交互会话保存与恢复（2026-10-09）

会话是持久化的 Lead 对话上下文，可包含多轮问答；从用户第一次有效交互时创建。

- 每个会话一个权威文件：`~/.agent-harness/sessions/<session_id>.json`，固定位置使任意启动目录都能按 ID 查找，
  不维护索引。只维护一种 JSON 格式，不保存版本号。
- 内容包含会话 ID、创建/更新时间、对话消息、交互事件、目标状态与目标事件；读取时校验必要字段。
  缺少必要字段、目录移动后恢复或结构不符时报错并保留原文件，不转换旧文件。
- 保存用同目录临时文件加 `os.replace` 原子替换；所有历史追加、原地替换和压缩替换都经过统一保存入口。
  保存失败时显示原因、当前交互继续，并在后续保存边界重试（dirty 重试）。
- 每次 Lead 模型响应的 API `input_tokens` 保存为 `model_usage` 摘要事件，不写入模型消息历史。
  底部读取当前会话最近一次测量，恢复后仍显示该数值；回合累计用量与单次上下文占用分开。
  有历史但无单次测量时显示 `暂无`，不把累计输入量或字符估算当成已用值；新的空会话显示 0。
- `/resume` 无参数时扫描 `sessions/` 按最近更新时间倒序列出有限条目；`/resume <id>` 读取并验证文件后，
  确认当前回合与后台任务已结束，保存当前上下文、切回原启动目录、恢复目标历史/目标状态/目标事件并设为当前会话。
- 恢复不请求模型；旧子 agent 线程、后台线程与 MCP 连接不恢复或重启。
- `/delete <id>` 删除指定的非活动会话；活动会话不能删除。读不出来的文件也在 `/resume` 列表中，可直接删除。
- 会话文件保存规范化启动目录绝对路径、Lead 活动任务 ID、会话工作树名称（无则 `null`）与 Todo；
  恢复时在原启动目录校验任务归属、状态、工作树绑定与目录有效性，失效则拒绝切换且当前上下文不变。
- 任务完成后清除任务分配但保留会话工作树；只有未关联工作树的会话使用启动目录。
- goal 状态恢复：当前活动条件、设置时间、评估次数、最近原因、连续阻止次数与最近状态；不恢复 token 起点或消耗。

## 6. Textual 界面（2026-10-09）

默认入口保持 CLI，新增 `agent-harness tui` 与源码入口；Textual 只作为可选依赖（`tui` extra，
`textual>=8.2.8,<9`），普通 CLI 与离线 workflow 不加载它。

- 核心执行沿用同步代码与现有线程：单 Lead 执行线程、CLI 唯一标准输入读取线程、Textual UI 线程；不做核心异步化。
- `runtime/interactive_runtime.py` 的 `InteractiveRuntime` 是 CLI/TUI 共用驱动，interface 为
  `start()` / `submit(text)` / `request_stop(turn_id)` / `close()`；停止与关闭只发请求，完成经事件通知。
- `runtime/interaction.py` 提供事件信封、`TurnOutcome`、提交结果、执行上下文、线程安全事件通道与一次性审批 rendezvous；
  审批请求带唯一 `request_id`、会话代次、执行来源、工具名与待确认参数。
- 审批必须等此前相关回合消息与工具调用展示完成后才交付前端；`InteractionChannel` 集中该条件，两个前端只报告展示完成。
- CLI 主线程是唯一 stdin 读取者，worker 只发布审批请求并等待响应；回合或命令真正结束后才恢复普通提示符。
- 停止是合作式请求，不中断进行中的同步网络调用；host 在模型请求前后、每个工具开始前及审批返回后检查停止标志。
  停止不批量终止其他子 agent、workflow 或后台任务，也不触发 goal 自动续做。
- 关闭顺序：标记 closing → 停止当前回合并结束审批等待 → 等待执行到达停止边界（不在 UI 线程阻塞获取 `agent_lock`）
  → 串行保存会话并报告结果、停止 cron 与后台 Lead 驱动、请求 persistent 子 agent 关闭 → 清理 shell 并等待有归属线程退出
  → 发布一次 `runtime_closed` 后释放 adapter。
- 命令补全：输入框键入 `/` 出现候选，前缀过滤、上下键选择、回车执行；`OptionList` 不获取焦点，App 转发导航。
  Esc 隐藏草稿保留，下次编辑重开；菜单只产生提交文本，业务由 runtime 执行。
- 命令目录统一在 `runtime/local_commands.py`，当前为 `/goal`、`/compact`、`/new`、`/resume`、`/delete`、`/quit`。
  菜单只展示已实现能力，不补全会话 ID、路径、工具名或 skills。
- TUI 当前为 CodeFox 工作台：顶部品牌栏与入口、左侧对话区、右侧只读会话状态（默认收起）、底部输入区；
  同次模型调用按关联 ID 分组，工具行摘要默认可见、详情可展开，模型/记忆等无参数无结果的状态行不显示详情块；
  Enter 发送，Shift+Enter 换行。
- 展示记录与恢复的语义：实时事实接受时交付并进入保存队列，检查点只消费和保存不重新交付；
  正文片段只用于实时显示，正式回复接受后才保存；恢复时未结束操作显示“上次中断，结束状态未记录”。

## 7. CodeFox 工作台前端（2026-10-10）

在现有 Textual 前端上深化，目标是会话历史、恢复、开启新会话、左侧对话上下文、右侧会话状态与交互输入都在一个工作台完成；
除“开启新会话”所需的最小运行时操作外复用现有后端。

- 顶部四个固定入口：`会话历史`（保存会话列表，恢复/删除）、`会话状态`（切换右侧只读面板显隐）、`开启新会话`（保存当前会话并创建干净新会话）、`设置`。
- `/new` 是运行时命令：保存当前会话并重置运行时上下文，前端不靠清空消息组件伪造新会话。

  本次进程不向损坏文件继续追加。写入失败保留内存待写记录，下一检查点重试；同一错误不反复提示，报错不递归写日志。
  删除会话先删日志再删 JSON，缺失日志不报错，失败明确报告；成功删除同时取消待写重试，不影响其他会话。
- `设置` 打开居中的设置弹窗，对话作为背景；`关闭` 或 Esc 关闭弹窗并恢复输入焦点、保留草稿。

  模型生命周期事件仍参与流式正文确认和恢复判断，但不再挂载为对话区的独立操作行。

## 8. 运行期职责深化（2026-10-10）

本阶段含同日的前一轮“整体架构职责收敛”与其后的“整体运行期职责深化”；同一事实在本文只有一处。

职责收敛（工具结果、Lead 上下文与 host 入口）：

- 工具在内部返回正文与明确执行状态（`ToolResult.status`），模型继续收到文本结果；失败由 Provider 按协议表达。
- 运行时持有唯一 `LeadContext`（`runtime/lead_context.py`）：Todo、会话 ID 与保留工作树归它所有；
  任务板只维护任务文件、依赖、认领、assignment 及其版本，不再保存会话 Todo 全局或保存回调。
- host 聚合重导出删除后，调用方直接导入真实职责 module。
- 失败结算策略：工具已成功、PostToolUse 失败 → Hook 失败写入诊断日志，保存真实工具结果，再停止当前执行，
  不把工具改成失败、不重跑；PreToolUse 抛异常 → 停止当前执行，handler 与 PostToolUse 不运行；
  普通工具失败 → 生成配对失败结果，同批其他工具按现有顺序继续；部分操作后失败 → 整体请求失败，
  正文列出已发生事实，保留资源与副作用，不自动重试或回滚。

工具调用协议与 Todo 边界：

- Provider 把 API 已标识的工具调用转成 `Block(type="tool_use", id, name, input=dict)`，同步与流式都遵守；
  普通文本中的 JSON 不作为工具调用执行。
- 协议解析失败（参数不完整、顶层非对象、调用未完整返回）抛 `ProtocolResponseError`，该响应整批不执行、不自动重试；
  Todo 参数检查失败（缺字段、类型或状态不符）只让该次调用返回错误 `tool_result`，原列表不变。
- `todo_write` 只接收协议层已解析的列表，检查每项为对象、`content` 为字符串、`status` 属于
  `pending`/`in_progress`/`completed`；通过后整份替换列表、发布 `todo_updated` 并保存检查点，返回清单统计。
  Todo 由模型明确提交；普通工具不自动改变 Todo，主循环不注入提醒。

运行期职责深化：

- 会话切换由 `runtime/session_switch.py` 的 `SessionSwitch.switch(target)` 独占：读快照、校验、停服务、chdir、
  激活归属、重启服务、发布 `session_changed` 都在实现内按序完成，失败回滚也在实现内。
- 命令路由由 `runtime/commands.py` 的 `CommandRouter.dispatch(text)` 处理本地命令并返回 `CommandOutcome`；
  `/resume` 委托 `SessionSwitch`。
- 回合执行由 `runtime/turn_runner.py` 的 `TurnRunner.run(submission_id, kind, text)` 拥有：接受到终态的事件、
  `_pending`/`_busy`/`_turn`/`_stop`、后台暂停与 lead 用量账本。
- `InteractiveRuntime` 负责生命周期、线程启动与关闭，以及展示事实的保存和交付；提交排队与回合状态归 `TurnRunner`。
- 子 agent 操作成为 Lead interface，模块级全局降为私有；锁序由单一私有 `_team_lock()` 上下文管理器强制，
  嵌套点统一经它进入；提供 `has_pending_inbox()` 与 `active_names()` 只读 interface。
- `agents/turn_engine.py` 的 `TurnEngine` 是 Lead、once 和 persistent 工作单元共用的完整模型—工具循环。
  引擎负责 `PromptState.prepare()`、`PreparedRequest` 快照、响应处理顺序、历史追加、消息与结果事件、
  工具批次配对、合法 `TurnPhase` 转换及终态；每个执行实例独立持有调用关联与阶段观察器。
  重试复用脱离可变历史的请求快照，压缩或工具结果更新历史后重新准备。
  `TurnCallbacks` 装配客户端所在的现有策略对象、上下文、system、工具池、模型请求、迭代前和完成前协调及单工具入口；
  单工具统一返回 `ToolExecution`，致命 Hook 错误先保存真实结果、补齐剩余 stopped 结果，再向外传播。
- `LeadTurn` 持有 Lead 恢复状态、cron 待交付和 Goal/memory 收尾；`SubagentSession` 持有子 agent 的
  注入配置、白名单、预算、提示词状态和单次上下文恢复。Lead 保留流式请求、重试、备用模型、额度升级与续写，
  子 agent 不采用 Lead 的输出恢复策略；`host.agent_loop(history, ...)` 仅装配现有入口，参数和 `TurnOutcome` 不变。
  普通工具审批与轮次间计划等待均进入 `waiting_approval`；嵌套 once 退出后恢复父 `phase_observer`。
  这些内部阶段不增加前端事件或会话字段。
- 工具结果契约在 `tools/tool_result.py`：`ToolResult` 携带不可变正文与状态
  （`returned`/`success`/`failed`/`denied`/`stopped`/`started`），状态不靠正文猜测。
- `frontends/conversation.py` 的 `ConversationProjection` 是共用展示投影：记录去重、工具关联、正文确认与作废；
  返回独立数据，不操作终端或控件。
- `ConversationView` 独占 TUI 对话区控件的挂载、清理和窗口重建；App 消费事件并调用视图，不直接维护控件索引。
  待确认消息、活动提示、错误提示与分组展开状态随当前视图恢复；切换会话清空临时内容，
  诊断日志按第 7 节从绑定文件恢复。

## 9. 权限规则与模式（2026-10-12）

- `runtime/permissions.py` 集中默认规则和权限模式；`hooks.permission_hook` 将判断接入现有审批通道。
  参数格式错误返回 `failed` 工具结果，不弹审批；文件不存在、系统读写权限和文本匹配错误由执行器实际执行后返回。
- 默认模式允许启动工作区内封装文件工具的读取、创建、覆盖和编辑；文件路径相对执行者当前任务目录解析，
  目录外读取和修改也可请求单次批准。审批与执行共用解析后的绝对目标路径，不授权整个目录或下一次调用。
  文件处理器只执行已授权路径，不重复检查工作区边界；glob 仍只返回执行目录内的匹配项。
- 单条普通 `pwd`、`ls`、`cat`、`git status`、`git diff` 按有限参数白名单免审批；未知选项、脚本、管道、
  重定向、连接命令、多行、变量展开和命令替换需要审批。不新增 Shell 解析依赖，也不提供 Bash 目录隔离。
- 禁止规则检查实际命令与参数，拒绝 `sudo`、关机、重启、`mkfs` 系列、带 `if=` 的 `dd` 和递归强制删除根目录的 `rm`；
  不因打印文本或文件名含有这些词而拒绝。有限命令分类不是完整 Shell 静态分析或系统沙箱。
- 权限模式是 `default`（默认）和 `no_approval`（免审批）；免审批直接允许原本需要询问的操作，包括目录外文件访问，
  仍执行参数校验、禁止命令和原有业务授权。MCP 沿用 registry 策略，显式拒绝仍拒绝。
- 当前用户设置位于 `~/.agent-harness/settings.json`，字段为 `permission_mode`；首次启动无文件时使用默认模式，
  非法结构或读取失败明确报错并保留文件，不转换或覆盖。启动时读取一次，新实例读取最新值，已运行实例不自动同步。
  保存采用同目录临时文件加原子替换，成功后才更新内存模式；保存失败维持原模式并提示。
- 左下角点击 `权限：默认 ▾` / `权限：免审批 ▾` 打开两项选择，免审批使用主题强调色；
  回合、命令执行和审批等待期间不可切换，运行时以提交共用的锁再次检查。审批卡显示操作类型与实际文件目标。
  审批等待或结束不改变模式；会话切换不重置模式，也不将权限设置写入模型历史或会话文件。
- CLI、TUI、子 agent 和自动任务共用规则；交互回合的执行上下文固定其开始时的模式，子 agent 继承该模式。
  默认模式下需要审批但无交互入口时不执行，返回审批不可用原因；免审批模式下直接执行。
  拒绝、停止和参数错误均沿用工具结果通道，用户和模型接收同一正文；CLI 不增加模式切换命令。

## 10. 提示词稳定化（2026-10-12）

- `context/prompt_state.py` 由 Lead 与子 agent 共用，首次请求生成固定 system 快照；身份、规则、
  启动目录和技能目录在同一周期复用。运行日期只精确到本地日，跨天追加通知，不改旧消息。
- Lead 的记忆目录、召回记忆、MCP 名称和活跃子 agent 名称，以及子 agent 的当前委派、任务、
  工作目录和计划状态，通过带 `_runtime_context` 标记的 `user` 文本追加到历史末尾。
  首次提供完整状态，之后仅通知变化；移除明确清空一次，名称排序，字段顺序固定。
- 通知声明其为运行状态或参考记忆，不是用户请求或授权；子 agent 以最新委派为准。
  通知只在工具结果补齐后追加，不生成页面消息或展示记录，不计入展示消息数量，记忆检索跳过它。
  发送与 token 计量都移除本地标记、保留正文；动态通知属于模型上下文。
- 会话 JSON 的可选 `prompt_state` 保存固定 system 和最新完整状态，与历史在同一检查点保存。
  缺少状态时在下一次请求初始化；已有状态结构错误则报错并保留文件。恢复复用快照，只通知当前变化；
  新会话独立初始化。子 agent 状态只跟随实例，不增加磁盘恢复能力。
- 自动、手动和被动压缩成功后重建快照并补充一次完整当前状态；失败保留原周期。
  自动压缩的阈值判断包含刷新后的 system 和完整通知。最新工具输出预算跳过末尾通知，字符存储限制不变。
- 每次新请求只装配一份 system、历史和工具快照，计量和发送共用；网络及输出额度重试不重复检索或追加通知。
  工具集合按名称排序，并反映实际能力增减。本实现只减少程序造成的前缀变化，不保证 API 平台缓存命中，
  不增加缓存统计、专用缓存参数或额外真实 API 请求。

## 11. 上下文输入预算（2026-10-14）

- `MODEL_CONTEXT_TOKENS` 配置当前模型与服务端共同支持的窗口；默认 258000 token。
  可用输入预算扣除升级输出额度 `ESCALATED_MAX_TOKENS` 和窗口的 10% 估算余量，非正预算在启动时报错。
- 自动压缩触发线、目标与最新工具批次预算分别为可用输入预算的 90%、80%、16%，
  请求估算包含 system、消息和工具定义。压缩摘要输入沿用压缩目标。
- 记忆召回按可用输入预算的 5%、20000 token 和正文 20000 字符共同限制；
  token 估算包含 JSON 来源信息与序列化开销，按相关性顺序截取。记忆仍默认关闭。
- 单条工具结果落盘默认 30000 字符，预览默认 1000 字符，分别由
  `TOOL_PERSIST_THRESHOLD_CHARS` / `TOOL_PREVIEW_CHARS` 覆盖，不随 token 窗口成比例变化。
