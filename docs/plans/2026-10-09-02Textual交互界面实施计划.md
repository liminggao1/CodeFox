# Textual 交互界面实施计划

> 制定时间：2026-10-09
> 状态：阶段一至七已实施；离线和终端验证已完成，真实 API 的 TUI 交互尚未实测
> 范围：增加 Textual 终端界面，保留 CLI；先建立共享交互执行、审批和关闭协议。

## 目标与约束

支持多轮对话、Markdown 回复、工具结果、子 Agent 和 workflow 进度，展示 TODO、goal、用量和运行状态，复用已有会话保存与恢复。

- 默认入口保持 CLI，新增 `agent-harness tui` 和源码运行入口。
- Agent 执行继续使用同步代码和现有线程，不做核心异步化重构。
- Textual 类型不进入 host、session、hooks 或工作流模块。
- 运行时状态继续跟随启动目录；同一启动目录只运行一个交互进程。
- 权限规则保持原有语义：Bash 均需确认，未明确允许的 MCP 工具需确认。界面迁移不重新定义“高风险”。
- 本计划保留实施依据，最终操作说明以 [开发笔记](../../note/dev-notes.md#textual-交互界面) 为准。
- 用户已许可新增依赖；WSL `learncc` 已安装 Textual 8.2.8，写入 `tui` 可选依赖，范围为 `>=8.2.8,<9`。界面使用自身事件循环消费事件，核心执行仍由现有线程承担。

## 职责与状态归属

| Module | 拥有的职责 | 不承担的职责 |
| --- | --- | --- |
| `interactive_runtime.py`（新增） | 交互实例生命周期、输入提交、本地命令、Lead 回合串行化、后台唤醒、会话切换、请求停止和关闭 | 控件操作、模型协议、权限判定 |
| `host.py` | 模型循环、工具执行、压缩、goal 评估；发布执行事件、检查停止请求并返回回合结果 | 解析用户命令、直接绘制界面 |
| `session_store.py` | `InteractiveSession`、历史、活动请求和持久化快照 | UI 状态、执行线程调度 |
| `hooks.py` | 权限判定、确定是否需要确认、将拒绝转交执行层 | 按钮、标准输入和线程间等待管理 |
| `interaction.py`（新增） | 普通事件交付和审批请求/响应协议；关联标识与线程安全传递 | 业务状态、权限规则、第二套持久化 |
| CLI adapter | 读取输入、文本渲染、收集审批决定 | 复制回合或会话切换逻辑 |
| `tui/` | 控件、布局、快捷键、事件呈现和审批弹窗 | 修改共享历史或直接执行 host |
| 现有 tasks、subagent、workflow、goal 模块 | 各自的业务状态和生命周期 | UI 专用状态 |

共享交互模块引用现有 `InteractiveSession` 和 goal，不创建另一套会话历史或 goal。UI 只保存输入草稿、面板选择和显示用副本；恢复会话时从权威快照重新构建显示。

命令解析与执行仅放在共享交互模块。CLI/TUI 只将输入交给它，不分别新增 `cli_commands.py` 和 `tui/commands.py`。必要时再拆私有实现，不预先增加只转发调用的文件。

## 共享交互 interface

拟提供 `start()`、`submit(text)`、`request_stop(turn_id)`、`close()`。停止和关闭只发出请求，完成通过事件通知；它们不等待执行线程或审批结果。状态通过事件和只读快照交付，审批响应通过 `interaction` 的请求 ID interface 返回。

`submit` 返回接受、忙碌或输入错误。接受时携带 `submission_id` 和输入类别（本地命令或模型回合），只是接收确认，不代表执行成功。用短时内部锁预留执行位置，返回前阻止第二次提交或后台回合抢占；不在 UI 线程等待 `agent_lock`、模型或磁盘操作。命令结果异步交付，执行完成后再释放位置；没有第二条普通用户输入队列。

交互模块负责完整输入路径：命令识别、UserPromptSubmit hook、补齐未完成工具结果、追加用户历史、记录会话、执行 host 和保存结果。后台通知也通过同一驱动路径进入 Lead。

- 复用 `agent_lock` 串行执行；UI 线程不得持有它等待执行完成。
- 运行中普通提交返回忙碌，首版不另建用户消息队列。
- `/goal`、`/resume`、`/delete` 的处理规则仅有一份；运行中拒绝修改会话状态的命令。
- `/resume` 保留当前限制：后台任务、子 Agent 或未消费 Lead 信箱仍存在时不切换。
- 保存失败不切换会话。任务板和 worktree 继续复用，线程和 MCP 连接不从历史快照恢复。
- 将 `host.async_event_loop()` 中的交互驱动与回复打印迁入共享模块，保持 cron、信箱和后台结果的原交付语义。
- 共享模块统一发布所有 Lead 回合的开始和结束，包括后台唤醒回合，避免 UI 只知道用户触发的忙碌状态。

### 回合结果

host 返回轻量 `TurnOutcome(status, reason)`，所有返回路径都明确结果；状态为 `completed`、`failed`、`stopped` 或 `truncated`。耗尽输出续写机会属于 `truncated`；工具拒绝作为工具结果交付，不自动视为整个回合失败。调用方不解析 `[Error]` 文本，也不从 `None` 返回值推断成功。

共享交互模块在 host 返回或异常后完成会话保存，并且恰好发布一次 `turn_finished`，包含 `turn_id`、关联提交、结果和停止原因。未处理异常转换为失败结果并释放执行位置；保存错误单独报告，不覆盖真实模型执行结果。`completed` 表示执行流程正常结束，不声称目标或文件已经验收通过。

### 本地命令与显示状态

每个已接受的命令交付一次 `command_result(submission_id, command, status, data)`：会话列表、goal 查询、删除结果和错误均使用结构化数据，不依赖模型回复或 `print()`。

`/goal <condition>` 设置成功时，`command_result` 携带预留的后续 `turn_id`，再启动与该提交关联的模型回合。CLI 要等这个回合的 `turn_finished` 才恢复普通输入。设置失败或其他本地命令的结果不带后续回合，以 `command_result` 为结束信号。拒绝的提交只有直接返回的拒绝结果，不产生假回合事件。终结结果发布前，驱动完成执行位置释放和生命周期登记，避免 CLI 看到完成后下一条输入仍被判忙碌。

共享模块在初始启动、命令完成、会话激活、业务状态变化后的安全边界和回合结束发布 `state_snapshot`。复制会话/goal/TODO 时持有 `agent_lock`，子 Agent 状态通过其拥有者的线程安全读取 interface 获取；序列化在执行侧完成。UI 消费快照副本，不锁住业务模块、扫描磁盘或读取可变全局量。快照携带相同代次与事件序号；UI 不用旧快照覆盖更晚状态。

## 普通事件协议

采用一个当前交互 adapter 和轻量线程安全通道，不建立通用广播总线。事件不替代会话、任务或 workflow journal 的权威存储。

事件信封包含：

- 单调递增 `sequence`：当前交互实例内的交付顺序，不声称代表跨线程真实发生时间；
- `session_id` 和 `generation`：会话关联与激活代次；未建立持久会话时 ID 可为空；
- `turn_id`、`source`：回合和 Lead/子 Agent/workflow/后台来源；
- `type`、`payload`：普通数据快照，不传入会继续修改的 history、SDK 对象或业务对象引用。
- `scope`：`session` 事件属于会话激活代次；`runtime` 事件属于当前交互实例，不关联会话或回合。

工具事件附带调用 ID；子 Agent 事件附带实例名；workflow 事件附带 run ID 和阶段。切换会话后提升激活代次，丢弃旧代次的排队事件，重新加载当前显示状态。
cron 服务跨会话存活，其通知使用 `runtime` 范围，不受会话代次过滤，也不提升 UI 的当前代次。两类事件共用单调序号；运行实例上下文不能申请审批。子 Agent 状态事件直接更新 UI 的显示副本，完整快照仍由执行侧在安全边界生成。

| 事件 | 唯一发布职责 |
| --- | --- |
| `user_message`、`session_changed`、`turn_started`、`turn_finished`、`command_result`、`state_snapshot`、`runtime_closed` | 共享交互模块 |
| `assistant_message`、`tool_call`、`tool_result`、Lead 模型用量 | host 的执行路径，结果写入历史后发布 |
| 子 Agent 状态、workflow 阶段/进度、后台任务状态 | 相应业务模块 |
| `session_saved`、会话保存错误 | 会话保存路径；只表示保存结果 |
| 审批请求 | hooks 通过审批 interface 请求，与通知事件分开处理 |

模型响应到达后交付完整文本块；首版不承诺 token 流式输出。保留工具调用前的助手文本，避免只展示最终答案。取消 `print_turn_assistants()` 的重复渲染路径，恢复历史也不重新发布成新的执行事件。

当前 host 的 `checkpoint()` 只是调用保存回调，不发布含糊的 `checkpoint` 事件。workflow 恢复点仍由 workflow journal 管理。

用量由真实请求结果提供，明确显示范围。首版展示可核实的 Lead 主模型请求累计用量；workflow、子 Agent 用量单独标注，不相加成未经去重的会话总量。辅助模型调用未计入时在字段名称中体现范围。

通知发布只交付数据，不执行渲染回调。TUI 在 UI 线程消费；CLI adapter 沿用原文本显示。显示事件队列不持久化，限制界面日志保留数量；消息、结束和错误事件不得静默丢弃，重复进度可合并。渲染异常不回滚业务结果。

## 审批 interface 与权限语义

hooks 保留拒绝列表、文件路径、MCP 策略和确认判定。审批 interface 只接收上下文并返回决定，不判断工具能否执行。

```text
hooks -> ApprovalRequest -> active interaction adapter
adapter -> ApprovalDecision -> waiting execution thread
```

迁移前基线并非“所有子 Agent 都不能确认”：`once` 在调用线程同步执行，从 CLI 主线程启动时可通过 hooks 请求审批。迁移后 [subagent.py](../../src/agent_harness/subagent.py) 与 [hooks.py](../../src/agent_harness/hooks.py) 使用显式执行上下文，按下表提供能力：

| 执行来源 | 是否可申请交互确认 | 上下文传播规则 |
| --- | --- | --- |
| 前台用户 Lead | 是 | 共享驱动创建前台回合上下文 |
| 前台 Lead 同步调用的 once 子 Agent | 是 | 同步委派继承前台回合的审批能力，保留子 Agent 身份和工具调用 ID |
| 后台唤醒的 Lead 及其 once 委派 | 否 | 创建后台上下文，不继承之前前台回合 |
| persistent 子 Agent | 否 | 创建独立非交互上下文，不继承创建者的审批能力 |
| workflow 步骤及格式修复调用 | 否 | 在 runner 入口显式创建 workflow 上下文，即使 workflow 由前台 Lead 调用也不继承 |
| 无交互上下文的直接调用 | 否 | 不按线程名、主线程身份或全局当前回合补充能力 |

表中能力只允许提出请求，拒绝列表、计划门禁、工具白名单和文件路径约束仍先行生效。用程序创建的执行上下文显式传递或在执行入口绑定，不把上下文作为模型可填写的工具参数。once 在不同来源的行为分别验证，不将权限收缩描述为保持现有行为。

- 请求包含唯一 `request_id`、会话代次、执行来源、工具名和完整待确认参数。
- 决定为批准、拒绝或交互已关闭；只允许指定请求接受一次决定，忽略迟到或重复回复。
- 无交互 adapter、请求停止或正在关闭时立即返回非批准结果，不无限等待。
- 待处理请求顺序呈现；需要审批的线程只等待自己的响应。停止/关闭先唤醒审批等待者，再等回合锁释放。

### CLI 标准输入归属

CLI adapter 的主线程是唯一标准输入读取者，使用现有 ConsoleBroker。worker 只发布审批请求并等待响应，不调用 `CONSOLE.ask()`。前台提交被接受后，CLI 暂停普通输入，持续消费输出事件；收到审批请求时由同一个读取者显示参数、读取决定并回传。回合或本地命令真正结束后才恢复普通提示符。

后台回合不能申请审批，因此后台输出不会与已经打开的普通输入争抢读取者。CLI 中 Ctrl+C/EOF 由 adapter 转成关闭请求；读取审批时的中断返回非批准结果再进入关闭流程。TUI 弹窗只响应指定请求，不消费普通输入框。两种 adapter 共享执行协议，输入等待方式可以不同。

## 请求停止与关闭协议

首版的“停止”是合作式请求，不保证中断正在进行的同步网络调用。Textual worker 取消不作为核心执行已经停止的证据。

- UI 设置回合停止标志并继续处理事件；正在进行的模型、重试、同步工具按现有超时完成。
- host 在模型请求前、返回后和每个工具开始前检查标志；权限确认返回后、真正启动工具前再次检查，避免批准与停止交错时仍启动副作用。
- 主模型返回上下文过长错误时，先检查停止，再决定是否启动恢复摘要。已请求停止或关闭时不发起摘要；原始模型异常仍为 `failed`，未确认 cron 按失败规则恢复。
- 收尾也检查停止：在正常 Stop hook、goal 评估、goal 续做消息提交和记忆抽取前检查。已经启动的评估/抽取允许返回，但返回后先检查停止，再决定后续动作；停止后不新发起评估、续做、抽取或归并请求。需要时向记忆抽取流程传入同一停止判定，覆盖抽取后继续归并的内部步骤。
- 对已写入历史但尚未执行的工具请求补齐明确的中断结果，保留已完成工具结果，不重跑副作用。
- 审批等待立即以非批准结果结束。停止回合不批量终止其他子 Agent、workflow 或后台任务。
- 停止不是正常完成，不触发 goal 自动续做或正常 Stop 流程；未确认 cron 交付按原失败规则保留。
- 已成功响应的模型请求仍按原规则确认 cron 已交付；停止工具执行不撤销这个确认。停止发生在模型调用前或失败路径时，才恢复尚未确认的 cron，避免重复投递。
- 共享交互模块在停止完成前暂停新的后台 Lead 唤醒，停止完成后保持暂停，避免 UI 刚停止就自动开启下一回合；后续显式提交恢复驱动。

停止只针对指定 `turn_id`。共享驱动用短时生命周期锁串行处理停止申请与结束登记：尚未登记结束时接受停止，并在终结时交付 `stopped`；已结束时返回“已结束”，不修改旧结果或停止下一回合。实际执行异常仍交付 `failed`，停止请求不掩盖错误。已经执行的 hook、评估结果或记忆写入不回滚，可能在下一检查点前完成。

正在执行的 once 委派或 workflow 是当前同步工具的一部分，首版等待它返回再停止父回合；不承诺递归取消。审批通道必须能在这段等待期间拒绝该前台回合的新审批请求。

关闭顺序：

1. 标记 closing，拒绝新的输入和后台 Lead 唤醒。
2. 请求停止当前回合，结束所有审批等待。
3. 保持 UI 响应，等待执行到达停止边界，不在 UI 线程阻塞获取 `agent_lock`。
4. 在串行访问下保存会话，报告保存成功或失败；停止 cron 入队和后台 Lead 驱动，请求 persistent 子 Agent 关闭。once 不支持关闭信箱协议，必须按前述当前工具等待规则结束。
5. 清理当前进程 shell，等待有归属的线程实际退出或报告其仍在关闭。persistent 的关闭响应不等于线程已经退出，需验证清理和活动登记移除。
6. 发布一次 `runtime_closed` 后释放 adapter，结束 UI。该事件携带最终保存结果；不能把仍在写会话的线程描述为已经关闭，保存失败不能显示为已保存。

实施基线阶段核对 cron 服务的停止方式和子 Agent 退出条件，必要时补充实例级停止信号；不改变持久任务、worktree 和信箱的归属。

## 实施阶段与验收

### 阶段一：行为基线与 interface 定稿

核对 cli、host、core、hooks、session、scheduler、subagent 的完整调用路径和直接输出点。确认权限来源、锁顺序、cron 交付、会话恢复与退出条件。

验收：记录源码证据和完整离线基线；对每类事件指定实际发布位置；确认上述停止与关闭协议可以落地后再写 TUI。

### 阶段二：最小交互协议与离线 adapter

建立 `interaction.py` 的事件信封、提交/命令结果、状态快照与审批请求/决定协议，定义执行上下文和 `TurnOutcome` 数据契约。先提供离线 adapter，验证线程间交付、请求关联、审批解除和数据副本。该阶段只建立协议，不迁移 CLI 行为。

已实施：新增 `interaction.py`，提供事件信封、`TurnOutcome`、提交结果、显式执行上下文、线程安全事件通道和一次性审批 rendezvous；新增 `tests/test_interaction.py` 覆盖并发事件顺序、JSON 数据副本、前台/后台审批矩阵、重复/迟到响应、停止/关闭解除和上下文不跨线程继承。该阶段未迁移 CLI、host 或 hooks。

验收：无需 Textual 或真实 API 就能验证交互契约；事件序号与入队顺序一致；迟到/重复审批不会解锁其他请求；不存在模块间循环依赖。已通过 `python -m pytest -q` 与 `python scripts/debug_pass.py`。

### 阶段三：共享交互驱动、CLI 与审批接入

按以下顺序拆分实施，每项完成后保留可运行的离线验证：

1. **共享驱动与回合入口**：提取交互驱动、本地命令和后台 Lead 唤醒；先接入 `start`、`submit`、回合串行化、事件/快照发布和 `TurnOutcome`，暂不改变 CLI 提示符。
2. **命令与会话接入**：迁移 `/goal`、`/resume`、`/delete` 的识别、会话切换和结构化 `command_result`；保存失败不得切换，会话限制保持一份。
3. **host 结果与显示事件**：让 host 执行路径发布助手、工具、用量和回合结束事件；移除重复打印路径，验证成功、失败、停止、截断四种结果和保存错误分离。
4. **审批与 CLI adapter**：迁移审批来源上下文，CLI 主线程成为唯一标准输入读取者；普通输入—等待回合/处理审批—恢复输入，不预设渲染文件数量。

验收：CLI 原有 goal、会话、后台交付行为保持；所有审批矩阵来源逐项通过；worker 不读取标准输入；没有第二套命令或历史；完成、失败和截断结果无需解析文本；输出无重复。

### 阶段四：停止与关闭完整接入

按以下顺序拆分实施：

1. **停止检查点**：接入 host 模型前后、工具前、审批返回后的停止检查；补齐未执行工具结果，保留已完成结果。
2. **收尾与后台恢复**：在 Stop hook、goal 评估、续做提交、记忆抽取/归并前后检查停止；暂停停止回合触发的后台 Lead 唤醒，显式新提交后再恢复。
3. **关闭与资源归属**：补齐 cron 交付确认/恢复、会话最终保存结果、cron 调度线程和 persistent 子 Agent 的退出追踪；每步保持原业务模块的资源归属，不用强制杀线程模拟正常结束。

迁移前的三个问题：`host.async_event_loop()` 在 `agent_lock` 内直接驱动后台回合；cron 为无停止条件的守护线程；persistent 关闭响应与实际退出分离。现已删除旧后台 Lead 驱动，cron 由可停止服务管理，persistent 与后台工具线程由所属模块追踪并在关闭时等待退出。

验收：在审批、模型返回、goal 评估、记忆抽取与同步委派期间请求停止，均按约定到达终态；等待审批时退出不会互锁；关闭完成后无执行线程继续写当前会话。上述协议验证完成后才接入 TUI。

### 阶段五：Textual 骨架

经依赖许可和官方接口核对后引入 Textual。首版目录按实际复杂度拆分：

```text
src/agent_harness/tui/
├── __init__.py
├── app.py
└── widgets.py
```

只有显示状态或渲染足够复杂时再增加对应文件。界面包括会话/模型/状态栏、对话区、工具与运行事件区、多行输入框。goal、TODO 和子 Agent 状态从权威状态派生。

验收：可离线启动和退出，控件只消费事件与快照；UI 状态不持有可写的共享业务对象。

### 阶段六：TUI 接入共享驱动

```text
Textual UI -> shared runtime.submit(text)
shared execution thread -> host.agent_loop()
interaction channel -> Textual UI updates
```

接入审批弹窗、会话恢复和后台唤醒。所有控件更新只在 UI 线程进行。

支持 `/goal`、`/goal <condition>`、`/goal clear`、`/resume`、`/resume <id>`、`/delete <id>`、`/quit`。TUI 的空白提交只忽略，不沿用 CLI 的空输入退出语义；CLI 保持原行为。

可选快捷键：Ctrl+L 清空输入、Ctrl+R 列出会话、Ctrl+C 请求停止回合、Ctrl+D 请求退出、F2 切换事件面板。快捷键只调用共享 interface。

验收：worker 不直接调用 CLI 处理函数或修改业务状态；UI 在模型请求、审批和关闭期间保持响应；后台回合也正确更新忙碌状态。

### 阶段七：集成验证与双入口

测试按行为组织，复用已有 fake client 和 session/workflow 测试，不为简单控件或转发函数单独建立测试层。

关键用例：

- CLI/TUI 同一输入产生等价历史与会话保存；运行中不会启动第二个 Lead 回合。
- 审批矩阵逐项验证，尤其前台同步 once 继承与 workflow/persistent 不继承；拒绝、重复响应、停止和等待审批时退出。
- CLI 前台运行时暂停普通读取，同步 once 发起审批不会等待普通输入锁；批准、拒绝和 EOF 均能结束正确请求。
- 模型成功、失败、停止与截断有独立结果；保存失败单独报告，结束事件恰好一次；迟到停止不影响下一回合。
- 会话列表、goal 查询、删除及错误有匹配的命令结果；goal 设置后 CLI 等待关联模型回合结束；TODO/goal 快照可更新界面而不直接读全局量。
- 工具前助手文本与最终回复不重复显示；多线程事件按来源关联。
- `/resume` 失败不切换，成功重建显示；旧激活代次事件不能污染恢复后的界面。
- 停止保留已完成结果、补齐未执行工具结果、不触发 goal 续做或再次自动唤醒。
- goal 评估和记忆抽取期间停止后不继续启动后续模型请求；cron 在响应前/后停止的确认规则分别验证。
- 关闭期间不接受新任务，审批已解除，后台执行不再写入关闭后的会话。
- cron、后台任务和信箱仍按原语义驱动 Lead；用量不被 workflow/子 Agent 重复累加。
- Textual 无头测试驱动完整离线对话、审批、退出、窄屏和滚动，并在 Linux PTY 验证中文、多行粘贴、发送和退出。

新增测试优先为 `test_interactive_runtime.py`、`test_interaction.py` 和 `test_tui_integration.py`，按实际需要扩展已有测试。

完整实现必须在 WSL `learncc` 跑：

```bash
python -m pytest -q
python scripts/debug_pass.py
```

入口：`agent-harness` 保持 CLI，`agent-harness tui` 启动 TUI。源码方式为 `PYTHONPATH=src python -m agent_harness tui`，不依赖安装。验证 plain CLI/workflow 路径不初始化 Textual；更新 README 与调试说明。

### 审查修正与验收（2026-10-09）

本轮补齐五项已确认缺口：停止或关闭后不再启动上下文错误恢复摘要；恢复会话后仍显示 cron 服务错误；后台 Lead 暂停时子 Agent 侧栏继续更新；失败命令结束忙碌显示并允许下一次输入；持久化 cron 仅由服务启动加载，重复加载不重复投递，也不覆盖正在处理的任务。

对应验证包括真实 cron 线程在恢复后报错、persistent 子 Agent 在停止后转为空闲并关闭、失败命令后再次提交、模型异常与停止/关闭交错，以及待投递 cron 的重复加载和确认。WSL `learncc` 全量测试 **338 项通过**，离线端到端自检 **9/9 通过**；其中 Textual 无头集成测试为 **8 项**。

会话切换时任务、worktree、TODO 及启动目录的恢复规则已由现有会话恢复实现明确，权威说明见 [交互会话保存与恢复计划](2026-10-09-01交互会话保存与恢复计划.md)。本轮没有新增需要决定的职责归属；真实 API 实测仍保留上述边界。
