# Textual 命令补全实施计划

状态：已实施。日期：2026-10-09。基线提交：`dc28376`。

## 目标与交付

在现有 TUI 输入框键入 `/`，立即出现本项目支持的命令及中文说明。继续输入前缀过滤候选，用上下键选择，回车执行选中的完整命令。需要必填参数时，先填入命令并提示参数，再回车执行。

沿用多行 `TextArea`、共享 `InteractiveRuntime.submit()`、审批和会话弹窗。不安装新依赖。普通消息仍为 Enter 换行、Ctrl+Enter 或发送按钮提交；本次新增的是单行本地命令的 Enter 操作。

交付范围为命令目录、输入框上方的候选面板、键盘操作、离线行为测试和使用说明。首版不增加新命令，不补全会话 ID、文件路径、工具名或 skills，也不增加模糊搜索、使用频率排序和独立命令面板。

### 项目现状与版本

调查日期为 2026-10-09。项目的 TUI 可选依赖为 `textual>=8.2.8,<9`，WSL `learncc` 实际安装 **8.2.8**。以下接口行为以该版本已安装的官方源码为准，在线文档作补充。

当前 `HarnessApp` 使用多行 `TextArea`；Enter 插入换行，Ctrl+Enter 通过 `action_send()` 提交。当前没有候选菜单，Textual 自带命令面板已禁用。现有离线 UI 测试使用 `app.run_test()` 和 Pilot，可以直接扩展，无须新依赖。

### 可复用接口与限制

| 能力 | 8.2.8 已核实行为 | 对本项目的意义 |
| --- | --- | --- |
| `Input(suggester=...)` | `SuggestFromList` 按给定顺序返回首个前缀匹配，显示单个行内建议；光标在末尾按右方向键接受；`Input.Submitted` 提交当前值 | 不能直接用于 `TextArea`，也不提供上下选择的候选菜单；保留现有多行编辑器 |
| `TextArea.Changed` | 内容变化后发送，含 `text_area` 引用，可从 `text_area.text` 读取草稿 | 重新计算命令名候选 |
| `TextArea.SelectionChanged` | 光标移动和选区变化均发送，含 `selection` 和 `text_area` | 光标离开命令词或出现选区时关闭菜单 |
| `OptionList` | 提供 `add_options()`、`clear_options()`、`highlighted`、`action_cursor_up/down()` 和 `action_select()`；`Option` 支持显示文本、稳定 `id` 和 `disabled` | 显示命令及说明；编辑器保留焦点，应用转发菜单导航动作 |
| `OptionHighlighted` / `OptionSelected` | 消息含 `option_id`、`option_index` 和 `option`；改变 `highlighted` 发前者，`action_select()` 发后者；禁用项不会选中 | 区分移动高亮和确认，确认统一走提交入口 |
| `ListView.Highlighted` / `Selected` | 同样支持导航和选择，候选由 `ListItem` widget 构成 | 可实现同类交互，但当前四项纯文本命令采用 `OptionList` 更简单 |
| `Binding(priority=True)` | 应用先检查优先绑定，再向当前焦点发送按键；`check_action()` 返回 `False` 后该绑定不处理按键 | 条件接管菜单操作，其余情况保持多行编辑 |
| `Message.stop()` / `prevent_default()` | 前者阻止向父节点冒泡，后者阻止随后调用继承层级中的默认 handler | 若使用编辑器子类，应同时调用二者，避免 Enter 同时执行和换行 |

来源：[8.2.8 Input 源码](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/widgets/_input.py)、[Suggester 源码](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/suggester.py)、[TextArea 源码](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/widgets/_text_area.py)、[OptionList 源码](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/widgets/_option_list.py)、[ListView 源码](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/widgets/_list_view.py)、[App 源码](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/app.py)、[Message 源码](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/message.py)。

### 键盘接入依据

采用公开的 App `Binding` 和 `check_action()`，不依赖私有 `_on_key`。条件包括当前为主屏、焦点在编辑器、草稿符合命令触发规则，以及相应的菜单或命令状态。上下仅在菜单有候选时启用，Esc 在菜单可见时启用，包括无匹配提示。Enter 的条件按下文交互契约处理。每次动作重新读取当前草稿和候选，避免滞后的 `Changed` 消息导致选择旧项。

不能只在 `HarnessApp.on_key()` 拦截 Enter：`TextArea._on_key()` 已在编辑器层插入换行并停止冒泡。若选择编辑器子类，可定义公开 `on_key()`，接管时同时调用 `stop()` 与 `prevent_default()`，其余情况让默认分派继续。不要手动调用 `super()._on_key()`；8.2.8 会沿 MRO 继续派发基类 handler，可能重复插入。

来源：[输入与优先绑定说明](https://textual.textualize.io/guide/input/#priority-bindings)、[动态 action](https://textual.textualize.io/guide/actions/#dynamic-actions)、[8.2.8 MessagePump handler 分派](https://github.com/Textualize/textual/blob/v8.2.8/src/textual/message_pump.py)、[TextArea 官方说明](https://textual.textualize.io/widgets/text_area/)、[OptionList 官方说明](https://textual.textualize.io/widgets/option_list/)。

## 命令与参数规则

候选来自共享命令目录。菜单展示名称、中文说明和用法提示，顺序固定如下。

| 候选 | 说明与用法 | 选中后 Enter |
| --- | --- | --- |
| `/goal` | 查看目标；`/goal <condition>` 设置并开始执行；`/goal clear` 清除 | 无参数时查询目标；已有参数时按原文本执行 |
| `/resume` | 打开保存的会话列表；`/resume <id>` 直接恢复 | 无参数时打开现有 `SessionScreen`；已有 ID 时交给驱动恢复 |
| `/delete` | 删除非活动会话；`/delete <id>` | 无参数时填入 `/delete `，显示“请输入会话 ID”，不提交；填写 ID 后提交 |
| `/quit` | 空闲时退出；运行中可用 Ctrl+D 请求关闭 | 空闲时走已有命令退出流程 |

`/goal clear` 的说明属于用法提示，首版不增加单独的子命令候选。运行层已有别名和参数检查保持其原语义。会话是否存在、能否恢复或删除、当前是否正在执行，由共享驱动及会话模块最终判断；菜单不是执行权限或状态的权威来源。

## 交互契约

### 触发与显示

1. 输入框获得焦点，主屏为当前屏幕，文本只有一行；允许前导空格，首个非空白字符必须是 `/`。
2. 没有文本选区，光标位于文本末尾、仍在命令名内时显示候选；`/` 显示全部四项，`/re` 仅显示 `/resume`。精确命令名排在首项，避免完整输入与默认高亮不一致。
3. 命令名后开始输入参数时隐藏候选，显示对应命令的用法提示。`/goal` 的任意条件文本不参与命令名过滤。
4. 中文自然语言、正文中间的 `/`、含额外目录分隔符的路径和多行粘贴不触发菜单。像 `/tmp` 这样与命令名外形相同的未知文本按无匹配处理；多行内容仍使用现有提交方式。
5. 无匹配项时显示“没有匹配命令”，不保留旧的高亮项。通过 Enter 选择命令的入口不把 `/resum` 等未完成名称交给模型。
6. 候选面板位于输入框上方，随可用高度限制行数并滚动；不作为模态弹窗，不抢输入焦点。窄屏隐藏侧栏后仍可使用；极矮屏优先保留输入框和至少一行候选。

### 按键与提交

| 状态/按键 | 行为 |
| --- | --- |
| 菜单有候选，↑ / ↓ | 移动高亮并滚动到可见位置；列表首尾循环；保持输入焦点 |
| 菜单有候选，Enter | 选择高亮项；参数齐备时提交一次，必填参数缺失时只填入并提示 |
| 已输入完整单行命令及参数，Enter | 提交原文本一次，驱动处理参数错误；不重新替换或丢弃参数 |
| 菜单有候选，Tab | 仅补全命令名；不执行，不自动填入示例参数或占位符 |
| 菜单显示，Esc | 隐藏菜单，保留原输入；同一文本的光标事件不立即重新打开，下一次修改文本才重新判断 |
| 菜单隐藏，↑ / ↓ / Tab | 保持 TextArea 编辑和原焦点切换行为 |
| 普通文本或多行文本，Enter | 保持换行 |
| Ctrl+Enter / 发送按钮 | 提交完整输入，不隐式选择候选；已知必填参数缺失时提示并保留输入 |
| 点击候选 | 与选中后 Enter 使用同一入口；提交前重新核对当前输入和 UI 状态 |

只有 runtime 返回 `accepted` 才清空草稿并隐藏候选。被拒绝时保留完整命令和参数；为前缀选择暂时构造出的完整命令也应回填到输入框，便于重试。一次按键不得同时提交候选和向 TextArea 插入换行。

Enter 的命令选择只适用于上述单行命令输入上下文。未匹配输入按 Enter 提示，不提交；Ctrl+Enter 和发送按钮仍保留提交普通消息的能力，包括用户有意发送的 slash 开头正文。

### 生命周期

执行中或关闭中隐藏候选并禁用命令 Enter 路径，保留草稿编辑。后台唤醒导致 busy 变化时同样适用；即使 UI 状态尚未刷新，最终提交仍由 runtime 拒绝并保留草稿。

审批弹窗、会话弹窗显示时隐藏候选；主屏的命令按键不得截获弹窗 Enter、Esc 和方向键。弹窗结束后按当前草稿重新判断。会话恢复成功后清除旧候选选择与隐藏记录，保留未提交草稿；从草稿重新计算候选。Ctrl+C、Ctrl+D、Ctrl+L、Ctrl+R、F2 保持现有职责，关闭和清空输入时清理候选状态。

## 职责与代码边界

| 位置 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 新增 `src/codefox/runtime/local_commands.py` | 定义不可变的四项命令规格：名称、说明、用法、是否需要参数；提供最小命令名查找 | 不导入 Textual、host 或会话模块，不包含执行函数或通用插件注册机制 |
| `interactive_runtime.py` | 用共享目录识别本地命令；继续执行现有 `_command` 分支并返回结构化结果 | 不管理候选、焦点和键盘，不为显示列表启动后台任务 |
| `tui/widgets.py` | 增加展示用候选面板，基于 `OptionList` 渲染说明和高亮，交付选择结果 | 不读取 SessionStore、goal、TODO、skills 或工具注册表，不直接执行命令 |
| `tui/app.py` | 监听文本/光标变化，过滤候选，协调条件按键、填入参数、提交及生命周期 | 不直接恢复或删除会话，不另建命令执行器，不持有可写业务对象 |
| CLI | 继续调用同一 runtime；自动使用同一命令识别目录 | 本次不增加 CLI 的提示符补全 |

命令目录是“支持哪些名称及如何提示”的唯一来源，`_command` 是“命令如何执行及哪些状态允许执行”的来源。新目录仅移走现有 `submit()` 中的四名称集合，并为 UI 增加只读元数据；不迁移 goal、会话或关闭职责，不复制参数解析和业务限制。

候选查询是本地同步计算，不需要新的 interaction 事件、查询线程或 runtime 请求。候选面板复用 `widgets.py`，不先创建通用补全框架。输入上下文及按键决策集中在 app 的一个小入口，避免 Enter、鼠标和按钮各维护一套参数缺失规则。

Textual 的具体接口和按键分派依据集中在上文“可复用接口与限制”和“键盘接入依据”，实现按该处接入，不另建编辑器分派机制。

## 实施任务与完成条件

### 一：命令目录收敛

- 建立最小只读命令规格及查找函数，让 `submit()` 从目录识别命令，保持其余执行路径和事件结构。
- 逐项核对 `/goal` 查询、清除和设置，`/resume` 列表和恢复，`/delete` 参数和活动会话限制，`/quit` 退出；扩展已有 runtime 测试中实际缺失的覆盖。
- 验收：CLI 和 TUI 可提交相同命令，普通消息分类不变；目录与识别没有第二份名称列表；纯 CLI 导入仍不加载 Textual。

### 二：候选展示与输入状态

- 在输入框上方挂载初始隐藏的候选面板，显示名称、说明和用法；监听文字及光标变化。
- 实现单行起始触发、前缀过滤、精确项优先、无匹配提示、参数阶段提示与 Esc 隐藏规则。
- 验收：输入 `/`、`/re`、删除前缀、移动光标和多行中文粘贴均符合契约；面板显示时仍能连续输入；窄屏和矮屏可选择候选。

### 三：选择、提交与生命周期

- 接入上下键、Tab、Enter 和鼠标选择；统一生成完整提交文本，经已有 `_submit()` 交给 runtime。
- 接入必填参数提示、拒绝时保留草稿、一次提交、忙碌状态及所有弹窗的按键边界。
- 验收：`/re` Enter 打开 SessionScreen；`/delete` Enter 不产生提交；填写 ID 后 Enter 才提交；审批弹窗 Enter 不会执行草稿；busy 拒绝不丢输入。

### 四：验证与文档收尾

## 已确定的取舍

本计划按“命令回车执行、普通多行输入继续换行”实施，避免把命令补全扩展为全局输入方式改造。当前四项命令足以形成可用入口，特别是 `/resume` 已有可键盘选择的会话列表，因此首版不需要动态会话参数补全。

如果后续希望普通消息也改为 Enter 发送，应单独确定换行键和终端兼容方式。若希望增加 `/help`、`/new`、skills 或工具命令，应先明确它们的运行层行为，再加入目录；菜单只展示已经实现的能力。
