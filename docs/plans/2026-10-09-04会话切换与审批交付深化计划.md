# 会话切换与审批交付深化计划

状态：已实施，两个候选均完成并通过验收。日期：2026-10-09。

## 问题与目标

本轮深化两个已选候选，先完成会话切换，再完成审批交付。

1. `/resume` 命令分支直接协调上下文、任务、目录和 cron；校验目标任务时还要临时修改 `core.WORKDIR`。
   将这些顺序规则集中在现有交互后端，并使目标目录校验不改变当前状态。
2. 事件与审批分别取出，TUI 自行判断是否已显示前置事件，CLI 的输出线程与输入线程也需要协调。
   将审批可以交付的条件集中在 `InteractionChannel`，两个前端只报告事件处理完成并展示请求。

提升 module 的 depth：interface 隐藏协作顺序，locality 集中到现有后端，leverage 覆盖 CLI 与 Textual 两个真实 adapters。
不以拆出函数、增加文件或缩短代码为完成标准。

## 已确认的行为

- 从任意目录按 ID 恢复，返回原启动目录，继承历史、goal、任务、工作树关联和 TODO；恢复本身不请求模型。
- 目标校验、当前会话保存或目录切换失败，保留当前上下文、目录和调度状态，并能继续交互。
- 目标上下文已激活后，记录 `resume` 事件的保存失败只报告错误；继续使用目标会话，下一次保存时重试。
  读取成功不等于写入成功，不为这个场景回滚到原会话。
- 审批提示必须等此前已发布的相关回合消息和工具调用完成展示后，才交给前端显示。
  子 agent 尚未发布的内部历史不因此新增为前端消息。
- 停止、关闭和会话切换后，过期审批不能执行工具；runtime 范围的 cron 日志仍能显示。

已有会话行为的权威说明见 [会话保存与恢复计划](2026-10-09-01交互会话保存与恢复计划.md)。

## 范围与职责

沿用同步模型调用、单 Lead 执行线程、CLI 唯一 stdin 读取线程和 Textual UI 线程。
会话保持一文件一种格式，位置保持 `~/.agent-harness/sessions/`。

不新增会话管理框架、索引、兼容层、迁移、依赖或跨文件事务。
不改变任务板、工作树清理、子 agent 生命周期、workflow resume 或权限判定。
不增加界面功能、命令补全或默认入口切换；并行命令补全计划仅需适配本轮交付 interface。

## 设计

### 会话切换

深化现有 `InteractiveRuntime`，不新增管理器 module。
内部恢复过程分为准备和激活两段；具体私有方法名称可随实现确定。

1. 准备：读取并验证上下文，重建 goal，按显式目标目录验证任务与工作树，检查后台执行和待交付结果。
   本段不改变 `cwd`、`WORKDIR`、当前会话、任务分配或调度登记。
2. 保存当前上下文；失败即返回，不进入激活。
3. 跨目录时停止 cron，并复查停止前可能新入队的结果，再切换目录。
   目录切换失败时恢复旧 cron，保留原登记；不清空旧状态。
4. 目录切换成功后，统一更新启动目录关联、goal、Lead 分配、TODO、历史与会话 ID，重置用量并推进代次。
5. 记录恢复事件并保存；保存失败时保留目标上下文、标记 dirty，结果同时体现已恢复和保存错误。
6. 跨目录时清除旧内存 cron 登记，并从目标目录加载持久化任务；按现有规则处理目标目录旧信箱。
   发布新会话事件与状态；CLI/TUI 不自行读取或替换这些状态。

显式目录只贯穿校验所需的任务读取、路径和 Git 查询，不推广成全项目配置重构。
沿用现有锁及既定顺序；不在持有 cron 锁时等待 cron 线程退出。
不承诺目录、多个文件和线程操作能组成一个原子事务。

### 审批交付

深化现有 `InteractionChannel`，保留事件与审批两种读取方式，满足 CLI 两线程与 TUI 单线程两种 adapters。

1. 审批入队时，在 channel 内记录它之前的事件序号，作为内部等待条件。
2. 增加 `acknowledge_event(sequence)`：adapter 成功处理事件后调用；只允许确认已交付的事件，不能提前确认尚未处理的通知。
   CLI 在 `render()` 返回后确认；TUI 在 `await _event()` 完成后确认。
3. `next_approval()` 只有在前置通知已确认、请求仍有效时才返回审批。
   未满足条件时非阻塞调用返回空，阻塞调用按既有 timeout 等待；不要求队列内所有后续事件都排空。
4. channel 集中过期会话通知与审批的过滤，丢弃的通知不再阻塞有效审批。
   runtime 范围通知不按会话代次过滤；取消和关闭仍直接解除等待。
5. TUI 删除“本批未排空所以不取审批”和重复的审批合法性判断。
   保留回合 ID、忙碌状态等展示信息；CLI 无需理解代次与前置事件顺序。
6. adapter 展示抛出异常时结束所属 runtime 或关闭审批，释放等待者；不能以未确认事件让执行线程永久等待。

不把 `acknowledge_event()` 暴露给模型，也不把展示确认写入会话文件。
审批判定仍由现有权限模块负责；channel 只负责交付、匹配与等待解除。

## 风险与重新计划条件

- 展示确认引入新的等待条件；必须覆盖两个前端及所有测试 adapters，避免执行线程等待永远不会到来的确认。
- 明确目标目录后不能漏传 Git 查询的目录；真实工作树测试验证目标仓库，而非当前仓库。
- cron 停止与入队可能交错；保留停线程后复查结果的规则，检查失败能继续旧会话。
- `tui/app.py`、`cli.py`、`interactive_runtime.py` 可能与命令补全实施重叠；执行前重新核对，只修改本计划负责的职责。
- 本轮无存储格式变更或数据删除等不可逆决策。内部 channel interface 直接更新全部调用者，不保留兼容实现。
- 若实现要求增加管理框架、改变单执行线程、恢复后台线程、引入跨文件事务、修改会话格式，或发现原行为保证无法实现，停止该部分并提交修订计划重新确认。
