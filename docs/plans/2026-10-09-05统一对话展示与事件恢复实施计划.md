日期：2026-10-09。版本：v3。状态：已实施、通过离线验收并合并到主分支。

## 1. 本次目标与基线

用户提交输入后，在同一个主对话区持续看到实际执行过程：处理请求、调用模型、运行 hook、调用工具、等待审批、子 agent 工作、工具返回，最后得到回答和回合结束信息。
工具的名称、关键参数和短结果默认可见，点击展开完整参数和长输出；同次模型调用的多工具过程组支持独立滚动。
Lead 面向用户的正文按模型返回的文字片段增量显示，不做完整响应返回后的逐字播放。
执行尚未结束时就能看到这些内容，不依赖回合结束后的集中回放。

**界面按用户提供的 Codex 截图改为纯会话：删除顶部状态栏、右侧事件和状态栏，只保留会话滚动区与底部输入区。**
用户消息、assistant 的过程说明、工具与 hook 条目、TODO、审批和最终回答都属于同一个回合，沿时间线显示。
忙闲、停止、关闭、保存成功或失败在当前回合内提示，不另设顶部仪表区。
底部输入区保留命令补全、发送、停止与必要快捷操作，不复制截图中本项目没有的模型切换或权限切换功能。
原始事件详情在对应记录内展开，不保留独立日志区，也不增加新的展示模式选择。
参考的是截图中的会话结构、紧凑操作条目和输入布局，不承诺终端 Textual 像素级复刻桌面应用；“Thinking”只用真实处理状态替代，不展示内部推理。

### 当前代码的缺口

| 可核实的现状 | 对用户的影响 | 本轮补齐 |
| --- | --- | --- |
| `frontends/tui/app.py` 的 `compose()` 创建顶部 `#status`、左侧对话和右侧 `#side/#state/#events` | 信息分散，窄屏还会隐藏右栏 | 删除顶部与右栏，只留会话和输入区，状态归入当前回合 |
| `frontends/tui/widgets.py` 把工具参数与结果全部放入默认折叠的 Collapsible | 默认只见工具名与状态，看不见正在操作什么 | 折叠区外显示操作摘要和短结果 |
| `runtime/hooks.py` 通过 terminal_print 输出 hook，TUI 把 log 放入右侧事件区 | 主对话看不到 hook，日志没有可靠生命周期 | 发布真实 hook 开始、返回和异常事实 |
| `InteractiveRuntime._checkpoint` 才生成并交付 display_record | Lead 长时间调用模型或工具时，后台事实无法及时进入主对话 | 事实接受时实时交付，检查点消费同一记录并保存 |
| `host.agent_loop` 收集整批工具结果后通过 append 发布 | 第一项工具已结束，仍可能等后续工具才能看见结果 | 每项结算后立即发布，模型结果批次保持原协议 |
| `agents/subagent_session.py` 内部工具未发布 tool_call/tool_result | 能看到子 agent 状态，却看不到其实际操作 | 从 child 真实执行入口发布事实并保留来源 |
| 输入接受与模型等待主要表现为状态栏“执行中” | 首次响应前，主对话可能长时间无变化 | 输入即时反馈和真实模型请求等待状态 |
| Lead 调用 messages.create；Responses 适配器在 _post 中一次性 read 响应 | 回复全文要等模型生成结束 | Anthropic/Responses 两种入口接入 Lead 正文流式，最终仍返回现有完整响应 |
| 现有 UI 测试主要渲染预先构造的完整记录 | 保存、恢复和最终顺序通过，不等于执行中可见 | 真实 runtime → UI 阻塞阶段验收 |

## 2. 输入后的可观察行为

1. 后端接受输入后，TUI 立即显示输入及“正在处理请求”；busy、invalid、closed 显示实际提示，不生成已接受的执行卡片。正式用户记录用 submission_id 替换临时反馈，避免重复。CLI 沿用已有输入方式，不重复回显。
2. 后端取得本轮会话 ID，正式发布用户记录，再运行 UserPromptSubmit。hook 有正确会话归属，不能丢掉首次输入的 hook。
3. 真实模型调用前显示“Lead 正在请求模型”或“某子 agent 正在请求模型”，调用返回或失败后结束等待。重试和续写只记录真实新请求，不显示虚构的思考内容。
4. 工具请求到达时显示执行者、工具名、关键参数和“待执行”。通过检查、即将进入 handler 时才显示“执行中”，等待审批时显示“等待你的决定”。
5. 实际执行的 hook 显示注册事件、callback 名称和进行中状态，结束后显示已返回、明确拒绝或异常。审批可发生在 PreToolUse 内部，不能提前把 hook 标成已通过。
6. 单项工具结算后立即显示短结果和可信状态，不等同批次其他工具结束。后续模型请求继续显示等待状态。
7. TODO 成功变化、子 agent 和后台状态在发生时进入主对话，标明来源。Lead 返回或下一保存检查点不能成为显示的前提。
8. Lead 正文在首个文字片段到达时开始显示，后续片段更新同一条 Markdown 回复。完整响应确认后收束为正式正文；回合结束显示真实完成、失败、停止或截断与已有统计。保存成功为轻量状态，失败明确提示。

普通聊天没有工具，就显示输入、模型等待、真实 hook 和回复，不强制经过 TODO、审批或子 agent。
有工具的回合先显示实际操作，再显示模型根据工具结果生成的回答。
模型中间主动输出的文本也正常显示，不把所有文本延迟到结束。
Stop、goal 检查或记忆整理若实际发生在回复文本之后，按真实顺序显示；收到回复不等于整个回合已经结束。

## 4. 实时交付与保存

### 事实转换只做一次

保留展示记录外层：id、at、kind=display、type、source、turn_id、payload。
稳定 ID 由通道生成，会话、代次和来源取自执行上下文。
工具按会话、回合、执行者、tool call ID 配对；hook 和模型请求另有 operation_id，开始、结束使用同一关联 ID。
不按工具名、callback 名称或屏幕文字合并调用。

将“检查点消费后生成”改为“事实被通道接受时生成”。
InteractiveRuntime 提供纯转换函数，输入事实副本，输出展示记录或明确不展示。
通道在确定发布顺序的临界区内调用它，将同一记录的独立副本交付前端并排入保存队列。
转换只用事实参数，不读写 session、Lead 历史、tasks、goal，不获取业务锁、不写文件、不调用模型。
后台因此可即时发布记录，不必等待 Lead 进入检查点。

_checkpoint 只消费已经生成的记录，按当前会话与代次校验、同 ID 追加和保存，不二次生成或交付。
原始通知可以更新当前回合的临时活动状态，但业务过程只渲染展示记录，不同时渲染原始工具通知。
状态快照只作界面状态副本，不逐次生成对话条目。
实时、保存、恢复的 ID 和顺序一致，重试不会生成新记录。
重复状态过滤须在两份副本产生前统一处理，或仅抑制重复显示；不能只删保存记录而保留不同的实时历史。
切换和关闭沿用原有规则，旧代次迟到事实不得进入新会话。

### 正文片段与完整响应

提供一个 Lead 使用的同步流式调用入口：接收当前请求、文字片段回调和停止查询，最终返回现有完整 Message 形态。
协议解析只在 providers 内完成。Anthropic 复用 SDK；Responses 处理流式分帧、UTF-8 跨片段、结束和错误，并由当前协议校验确认最终响应。
不把主循环改成异步，不把协议事件直接交给前端；其他内部 create 调用保留现有用途。

每次真实请求尝试分配 model_call_id；文本块有稳定块索引，工具记录保留产生它的 model_call_id。
同次调用的工具因此可归入同一过程组。重试、续写和 child 调用有各自身份，不靠相邻显示或工具名猜分组。
Lead 发布临时 assistant_text_delta，包含调用身份、块索引、片段顺序和正文增量。
UI 以会话、代次、执行者、调用身份和块索引更新同一条正文；CLI 在原输出位置追加，不在结束时再打印一遍全文。
按既有 UI 刷新节奏合并相邻片段，保持原顺序；不为每个字符挂载控件或写一次文件。

片段只用于实时展示，不加入 DISPLAY_FACT_TYPES 的持久记录集合，也不逐片段修改模型历史。
完整响应返回后，先经过原 accept_response 和协议校验，再追加正式消息、发布带对应调用身份的 assistant_message 并保存。
正式消息到达时确认或替换临时正文，不能再生成第二条相同回复。没有文本块的工具响应不创建空回复。
流式工具参数在 providers 聚合；工具批次完整、校验通过且原恢复规则接受后，才发布正式 tool_call 和进入执行路径。
不能因收到部分名称或参数就执行工具；不显示隐藏推理、内部记忆或协议原始帧。

断流、异常、取消或首次 max_tokens 触发重试时，旧临时正文结束并标明“本次输出未采用”，默认收起其内容；新尝试使用新身份。
旧片段不混入新回复，不加入正式模型历史，也不能只把失败的临时内容无提示地清空。
accepted 的截断正文和续写沿用当前恢复规则，明确标识截断，不将它们误称为完整最终回答。
用户停止时立即显示“正在停止”，在下一读取/处理安全点停止交付正文并关闭流，结束状态走既有 stopped 规则。
网络读取仍受既有超时限制，不承诺阻塞读取中瞬时终止；用户主动停止不能被重试当作网络失败重发请求。
每次调用的 usage 只从最终有效用量记录一次，不按片段累计，不因正文确认或恢复重复统计。

### 生命周期事实

保留消息、tool_call/tool_result、TODO、审批、后台状态和回合结束的已有用途。
新增一种 execution_status，表达模型请求、工具实际进入 handler、hook、goal 检查和记忆整理的真实生命周期。
payload 至少有 operation_id、phase、name、state；关联工具时有 tool_call_id，hook 有注册事件名和 callback 名。
phase、state 的允许值明确列入校验：开始、返回、失败、明确拒绝等必须对应真实路径，不靠日志文字猜测。
goal 与记忆整理只在实际进入操作时发布，用于解释回复后尚未完成的等待，不扩展为全部底层调用追踪。

hook 在 trigger_hooks 内围绕 callback 发布，每次实际 callback 各有生命周期，没有 callback 就不显示已执行。
None 只表示本回调没有阻止链，不能表示工具成功或任务核验通过。
非 None 保留类别；只有实际拒绝分支才显示拒绝，不把所有事件的非 None 都当权限拒绝。
异常先发布失败事实，再按原契约传播；不吞异常、不重复 callback。
权限 hook 等待审批时保持未完成，后续未调用 callback 不产生记录。

tool_call 表示请求到达，不能把同一模型响应的所有工具都标成执行中。
每项工具结算后发布一次 tool_result，包含拒绝、未执行、异常和后台启动分支。
模型整批结果消息的追加不再重复发布这些结果。
handler 已返回但 PostToolUse 尚未结束时，显示正在后置处理；整体结果不能提前假装完成。
child 使用真实入口和已有 on_status 等依据，未知字符串结果仍是“已返回结果”。
未知、不可用、门禁拒绝的工具没有 handler 开始记录，但保留请求与拒绝事实。
后台启动不等于完成；后续完成通过实际后台状态表达。
workflow 中沿用执行上下文的 child 可见，不给没有事实的任意 Python 步骤补造追踪。

### 保留既有保存边界

会话仍在 `~/.agent-harness/sessions/<id>.json`，events 保存展示事实，messages 供模型与压缩使用，展示记录不整体进入模型输入。
保存只由 Lead 执行线程在检查点完成，不等待前端、不在通道锁中写文件。
消息继续“追加历史 → 发布事实 → 检查点”；工具请求仍在执行前检查点。
审批请求、决定仍经过保存尝试和前置展示确认屏障，按钮仍以 next_approval 的有效请求为准。

实时单项结果可早于模型整批结果追加，不能为显示而发送残缺批次。
中途保存允许展示事实领先模型历史。
恢复必须区分“执行结果已记录”和“模型结果批次未写完”，沿用中断回合的协议收尾，不能重跑工具或把真实结果说成未执行。
这一交界用真实文件验证，不凭 UI 外观判断协议完整。

后台在长调用中发布的新事实即时可见，但到下一检查点才落盘。
这段时间异常退出可能丢失未保存事实，UI 不能把显示完成当保存成功，不新增保存线程。
保存失败保留内存记录、dirty 重试；保存提示不反过来触发保存。
流式临时文字同样不保证恢复；只有正式消息在检查点保存后进入恢复历史。
历史可保留该模型操作的开始/失败事实，不能补造未落盘的临时文字或自动重发请求。

/resume 只读回放，不执行旧模型、hook、工具或子 agent。
未结束操作显示“上次中断，结束状态未记录”，没有动画和审批按钮，不推断副作用。
重复恢复不追加相同中断提示，结束摘要不重新统计。
新增类型直接扩展当前校验，不增加格式版本、回填、迁移或旧读取分支。
原文件符合当前结构仍可恢复，不强制历史中必须有新生命周期事实；非法文件按 [正向开发规范](../../AGENTS.md#正向开发) 报错并保留。

## 7. 验收与运行命令

使用已有 fake client、真实 runtime、线程 Event 屏障、临时会话文件和 Textual 无头运行，不安装依赖。
流式协议用本地 HTTP 服务发送分段帧；Lead fake client 实现正式流式入口，不通过无流式能力时退回 create 来掩盖问题。
测试在屏障尚未释放时断言过程可见，不只查看结束后的完整记录。

- **输入与模型：**真实模型被阻塞时，主区已有输入和等待状态；接受记录合并后无重复，拒绝输入无假运行。命令补全回车执行仍正常。
- **首片段与确认：**两种协议在最终响应尚未返回时交付可见文字；跨片段中文、多文本块和连续增量正确；结束后正文和 usage 只出现一次，临时片段不进入会话文件。

- **流式恢复与停止：**首片段前后故障、429/529 重试、首次 max_tokens 升级与后续续写、用户停止、关闭和旧代次迟到片段均不混合尝试；停止不会自动重发。
- **hook：**callback 被阻塞时已显示事件、名称和进行中；放行、非 None、异常、无 callback 和审批阻塞只产生真实状态，异常不吞掉。
- **快慢工具：**同批第一个完成、第二个阻塞，释放第二个前 UI 已有首个短结果和第二个执行状态；模型消息批次合法，结果与统计不重复。
- **后台实时：**Lead 在长调用中，独立线程发布 child/后台事实，UI 在 Lead 返回前可见；下一检查点文件保存同 ID、同顺序。
- **child 真入口：**once/persistent 通过 SubagentSession.run 调用真实工具，来源正确；workflow 的已有上下文也覆盖，不用手工塞展示记录代替执行。

## 8. 风险与重新规划条件

| 风险 | 约束 |
| --- | --- |
| 转换前移后后台获取业务锁而死锁 | 转换只用事实，通道内无 I/O 与业务锁 |
| 实时交付绕过审批显示确认 | 保留 sequence/acknowledge 屏障，真审批回归 |
| 逐项结果与整批消息重复发布 | 唯一结果发布路径，按调用 ID/记录 ID 验证 |
| 显示完成被误认为保存完成 | 只依据实际 save 返回更新保存状态 |
| 删顶部与右栏丢失提示或持续刷 snapshot | 错误进当前回合，快照只更新状态，日志有显示上限 |
| 卡片聚合错配或遗失来源 | 保存事实顺序，展示按完整关联键投影 |
| 流式失败或重试混入已显示文字 | 每次尝试独立身份，失败临时正文标明未采用，正式确认替换不重复 |
| 部分工具参数提前进入执行 | 完整协议响应校验与原 accept_response 通过后才执行整批工具 |
| 高频片段拖慢 UI 或反复落盘 | 按刷新批次合并展示，片段不持久化，不逐字符挂载控件 |
| 多工具滚动藏住审批或打断阅读 | 审批操作独立可见，内外滚动分工，更新保留视口 |
| 07 共用执行抽取引起重复 hook/事实 | 实施前选定顺序，同一入口只发布一次 |

若必须改变审批语义、线程生命周期、工具模型协议或新增独立保存机制才能达标，返回规划阶段。
