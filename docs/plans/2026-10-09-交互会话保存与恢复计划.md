# 交互会话保存与恢复计划

> 制定时间：2026-10-09。
> 状态：已实施。
> 范围：交互 CLI 的多会话保存与 `/resume <id>` 恢复。

## 目标

会话从用户第一次有效交互时创建。一个会话可以包含多轮问答；所有问答共同构成一个持续更新的会话上下文。
每次历史变化都更新同一个会话存储，之后输入 `/resume <id>` 可以读取该存储，继续使用当前模型和工具。

会话数据没有“正常完成”“中断完成”等持久化状态。需要区分的是：

- **持久化会话**：保存在磁盘上的对话上下文，可以长期保留和再次恢复。
- **活动会话实例**：某个 CLI 进程当前正在使用的会话。`q`、`exit`、空输入、EOF、`Ctrl+C` 或异常会结束这个实例，但不会删除持久化会话。

`/resume` 的前提是当前会话实例先结束。当前 CLI 进程可以在保存并结束当前实例后切换到另一个会话；如果当前模型回合或后台任务仍在运行，恢复操作暂缓，不切换上下文。
项目按同一启动目录只运行一个 CLI 进程处理会话，不实现多个进程同时写同一会话的合并。

`workflow resume` 继续只负责工作流 journal，不与交互会话恢复合并。

这里的会话指一个持久化的 Lead 对话上下文，不是一次 CLI 进程或单个用户问题。模型请求、工具调用结果、后台事件注入的消息和
goal 状态属于会话内容；任务板、memory、MCP 连接、子 agent 线程和 worktree 属于运行时状态。
任务板和 worktree 记录本身继续保留，恢复后如果任务和 worktree 仍然有效，Lead 可以继续使用原工作树；旧的子 agent 线程、后台线程和 MCP 连接不会恢复或重启。

## 设计

1. 在 `.transcripts/sessions/<session_id>.json` 保存每个会话；每个会话只有一个权威文件。
2. 会话文件使用带版本号的 JSON，包含会话 ID、创建/更新时间、对话消息、交互事件、goal 快照和 goal 事件。
3. goal 快照第一版只恢复：当前活动条件、设置时间、评估次数、最近原因、连续阻止次数和最近状态；不恢复 token 起点或 token 消耗。恢复后继续使用当前进程的评估器和当前配置。
4. `/resume` 不带 ID 时扫描 `sessions/` 目录，读取每个合法会话文件的元数据，按最近更新时间倒序列出有限条目；不维护额外索引。
5. 会话文件使用同目录临时文件加 `os.replace` 原子替换，避免进程中断留下半个文件。
6. 内容块递归转换为 JSON 字典，至少保留 `type`、`text`、`id`、`name`、`input`、`tool_use_id` 和 `content` 等字段；恢复后统一使用字典，现有请求转换、压缩和展示逻辑均可读取。
7. 所有历史追加、原地替换和压缩替换都经过统一的会话保存入口。入口在变更成功后保存当前完整上下文；不把问答拆成不同会话。
8. `/resume <id>` 先确认当前模型回合和后台任务已经结束，保存当前会话并结束当前活动实例，再读取指定文件，恢复历史、goal 快照和 goal 事件，把该会话设为新的活动实例。
9. `/delete <id>` 删除指定的非活动会话文件，不进入模型历史；当前进程正在使用的会话不能删除。

会话 ID 在第一次有效交互时生成，使用 UTC 时间加短随机后缀，例如 `20261009-143012-a1b2`；它只用于本地文件名和命令参数，不代表模型或远程服务中的 ID。
命令只接受完整、合法的会话 ID，不接受路径片段或模糊前缀。

## 命令语义

| 输入 | 行为 | 是否调用模型 |
| --- | --- | --- |
| `/resume` | 列出可恢复会话，不改变当前上下文 | 否 |
| `/resume <id>` | 保存并结束当前活动实例后读取指定会话；模型回合或后台任务未结束时暂缓 | 否 |
| `/delete <id>` | 删除指定的非活动会话；指定当前活动会话时拒绝 | 否 |
| `/goal` | 查询当前目标并记录交互事件 | 否 |
| `/goal clear` | 清除当前目标并记录交互事件 | 否 |
| `/goal <condition>` | 先保存目标设置事件，再把 condition 作为当前请求执行 | 是 |
| 普通问题 | 追加用户消息，执行 Lead 回合 | 是 |
| `q`、`exit`、空输入 | 结束当前 CLI 进程，保留最后快照 | 否 |

`/resume` 不自动触发模型请求。恢复后的下一条普通问题才会使用恢复的历史。
没有会话、ID 不存在、版本不支持或文件损坏时，只提示错误并保留当前内存状态。
当前进程有活动会话时，`/resume <id>` 会先保存当前上下文。当前模型回合或后台任务未结束时只提示稍后重试，不修改当前历史；条件满足后才切换会话。

`/resume`、`/delete` 和 `/goal` 都是用户侧 CLI 命令，不注册为 LLM tool：它们负责切换或修改会话上下文和持久化状态，
必须在模型调用前由用户明确触发，也不应进入模型对话历史。

## 会话存储规则

- CLI 启动时不创建会话。除 `q`、`exit`、空输入、EOF、`/resume` 和 `/delete` 外，用户一旦进行交互就创建或更新会话，包括单独查询 `/goal`。
- `/goal <condition>` 必须先保存 goal 设置事件，再开始模型调用；这样模型处理中断时，恢复后仍保留目标。
- `/goal` 查询、设置或清除、普通用户消息、助手响应、工具结果、压缩替换和已交付后台通知，都通过统一入口更新同一个会话快照。
- 没有活动会话时，后台事件不能创建会话。后台事件只属于创建它的活动会话实例。
- q/exit/EOF/Ctrl+C/异常退出或会话切换时停止当前实例的后台事件接收；后台线程和后台任务属于当前实例，实例结束后不再向新会话写入。未完成的后台结果不由 `/resume` 恢复。
- `/resume <id>` 在当前模型回合和后台任务都结束后保存并结束当前活动实例，再恢复指定会话；恢复成功后，后续交互继续写回该 ID。
- `/delete <id>` 只能删除非活动会话文件，不删除任务板、memory、工作树或其它运行时记录。
- 任务记录和 worktree 记录不复制到会话文件；它们仍按启动目录持久化。恢复后通过现有任务分配和 worktree 校验继续使用有效工作树。
- `/resume` 默认扫描 `sessions/`，按会话文件的更新时间倒序显示有限条目；损坏或版本不支持的文件单独提示，不影响其它会话列出。

## 保存失败和一致性

保存可能因为目录不存在、权限不足、磁盘空间不足、临时文件替换失败、内容无法序列化、文件损坏或进程在写入过程中被终止而失败。

处理规则如下：

1. 保存入口捕获可预期的本地存储错误，向终端提示失败原因，不中断当前模型回合，不回滚内存中的历史。
2. 保存失败时标记当前上下文为 dirty；下一次历史变化或回合结束时再次尝试保存。
3. 原子替换保证目标文件不会写成半个 JSON；目录扫描时只读取完整且通过版本校验的会话文件。
4. 删除时直接删除会话文件。删除成功后，该文件不再出现在下一次目录扫描中。
5. 同一启动目录默认只有一个 CLI 进程写会话；不处理多个进程同时修改同一个会话造成的合并冲突。

## 交互事件和 goal 快照

每个交互事件至少包含：事件 ID、UTC 时间、事件类型、相关文本摘要、处理结果和保存时的消息数量。事件类型包括普通用户输入、`goal_query`、`goal_set`、`goal_clear`、模型回合完成、后台通知和恢复。

goal 快照至少包含：

- `active`：当前活动目标或 `null`；
- 活动目标的 `condition`、`set_at`、`iterations`、`last_reason`；
- `consecutive_blocks`；
- `last_status`；
- 完整 `events` 列表。

第一版不保存或恢复 token 统计，避免当前实现中 token 计数来源不一致。

## 取舍与后续扩展

每次首次交互建立独立会话文件，能保留不同工作的上下文；目录扫描足以支持本地单用户场景，不额外维护索引。
初版提供显式 `/delete <id>`，不自动删除旧会话，不做多进程合并和远程同步；后续如需控制磁盘增长，再增加保留策略。

恢复只负责会话历史和 goal 上下文。任务板和 worktree 继续由自己的持久化机制管理，因此恢复后可以继续原任务工作树，但不会把旧线程或连接带回来。

## 验收条件

- 首次有效交互后，启动目录下出现唯一 ID 的 `.transcripts/sessions/<id>.json`；只启动并退出、只输入管理命令或后台无用户交互时不创建会话。
- 用户消息、助手回答、工具结果、错误响应、续写提示、压缩替换和已交付后台通知都通过统一入口更新会话快照。
- `/goal <condition>` 在模型调用前已保存 goal 设置事件；恢复后活动目标、评估次数、最近原因、连续阻止次数和最近状态保持一致。
- 输入 `/resume` 能看到会话；当前会话保存并结束后输入 `/resume <id>`，后续模型请求收到指定历史，并继续写回原 ID。
- 当前模型回合或后台任务未结束时，`/resume <id>` 不替换历史并提示稍后重试；条件满足后可以在同一进程完成会话切换。
- 恢复后，仍然有效的任务和 worktree 可以继续使用；旧子 agent、后台线程和 MCP 连接不会恢复。
- 保存的工具调用、工具结果、中文文本和压缩归档标记可再次读取。
- 保存失败时终端显示原因，当前交互继续执行，并在后续保存边界重试。
- 没有会话、ID 不存在、版本不支持或文件损坏时，命令给出提示，不调用模型且不崩溃。
- `/delete <id>` 删除非活动会话后，该会话不再出现在 `/resume` 列表中；删除活动会话时给出提示且上下文不变。
- `Ctrl+C` 或模型处理中断后，最近一次已经追加到历史的完整上下文仍可通过新进程的 `/resume <id>` 恢复；未提交到历史的局部结果不保证保存。
- `/resume`、`/delete` 和 `/goal` 命令本身不会写入模型历史；`/resume` 不消耗模型额度。
- `workflow resume` 的原有行为和现有测试保持不变。
