# CodeFox 工作台前端实施计划

日期：2026-10-10。版本：v21。状态：UI 草图重新设计，待修复后重新验收。

本计划参考用户提供的会话式 Code Agent 界面和 MokioClaw TUI 截图，深化现有 Textual 前端。目标是让用户可以从一个工作台完成会话历史、恢复、开启新会话、左侧对话上下文查看、右侧会话状态查看和交互输入；除“开启新会话”所需的最小运行时操作外，继续复用当前后端能力。

## 1. 目标与边界

### 1.1 目标

- 在顶部提供当前会话标题和三个固定入口：`会话历史`、`设置`、`开启新会话`。
- 在中部保留当前对话和执行事件流，继续使用后端保存的展示记录恢复历史。
- 在底部提供输入框、发送/停止、当前模型、消息数量、字符预算和已有权限状态。
- 使用现有 `assets/logo/1F98A.svg` 的狐狸头像，品牌文字只显示 `CodeFox`，不添加额外装饰符号。
- 窄终端仍可完成输入、发送、停止、审批、恢复和退出。

### 1.2 不纳入本计划

- 不实现新的工作目录、任务、TODO、审批或模型后端能力；“开启新会话”只增加保存当前会话并重置运行时上下文的最小操作。
- 不加入思考强度选择。当前后端没有 thinking/effort 字段或设置接口，界面不伪造 `High` 等值。
- 不加入权限模式切换、全权限开关或权限配置页。现有权限规则仍由 `permission_hook`、工具注册器和审批通道决定。
- 不加入模型切换、API 配置、主题编辑、插件市场、Trace 开关或通用设置存储。当前后端没有对应的运行时设置协议。
- 不重做会话文件、展示记录、事件顺序、审批确认屏障、恢复目录和共享 `InteractiveRuntime`。
- “开启新会话”需要共享运行时提供清晰的重置边界；前端不能只清空消息组件来伪造新会话。若后端尚未提供该能力，先补运行时命令和测试，再接入按钮。
- 不下载外部图片或引入新的 Logo；只引用仓库已有 SVG。

### 1.3 执行边界

- 本计划只改现有 Textual 入口、展示格式化和为展示所需的最小状态投影，并补充“开启新会话”所需的运行时命令；不改变模型调用、工具执行或会话文件结构。
- 顶部“会话历史”只打开保存会话列表并提供恢复/删除；当前会话的历史仍在对话区通过“加载更早记录”查看。它不是新的历史存储或新的后端命令。
- 顶部只保留三个按钮，职责必须彼此独立：`会话历史`打开保存会话列表并提供恢复和删除；`设置`打开只读运行信息；`开启新会话`请求运行时保存当前会话并创建干净的新会话。
- 顶部“设置”与右侧会话状态使用同一组只读格式化函数。设置面板只提供窄屏或需要集中查看时的替代入口，不维护第二份状态。
- 会话标题由已有会话 ID 和首条用户交互摘要组合得到；当前后端没有独立标题字段时不增加标题写入。
- 右侧会话状态默认收起；收起时对话区占满整个主体宽度，入口是对话区顶部行右侧的 `[状态]` 按钮，不保留窄列。输入区、草稿和事件流不丢失，也不常驻会话摘要。
- 状态面板展开时出现在主体右侧，标题行自带 `[收起]`；收起后入口回到对话区顶部行右侧的 `[状态]`。窄屏复用同一个 `[状态]` 入口打开状态面板。`[状态]` 是面板入口，不计入顶部三个固定按钮（会话历史、设置、开启新会话）。
- 右侧状态只显示后端已经能提供的字段。工作目录、任务 ID 和工作树已由 `state_snapshot` 的 `workdir`/`task_id`/`worktree` 提供，直接投影；前端不读取会话文件。
- 耗时以展示记录中的开始/结束事件或已保存的回合摘要为准；只有开始时间而没有结束事件时显示“进行中”，恢复后沿用记录时间计算，不凭前端刷新时间伪造完成耗时。
- 进行中事件首次显示时就要带上“进行中 · 已耗时 0.0s”或等价文案；前端计时器只刷新这个已存在的进行中显示，结束、失败、停止后固定为后端事件确认的总耗时。历史记录没有结束事件时保持“上次中断”，不能显示 0 秒完成耗时。
- 命令结果的错误必须在当前前端可见，即使该结果已经写入会话展示记录；删除成功后要重新请求会话列表，删除当前会话失败时保留当前对话并显示后端错误。
- 当前工作树可能包含其他任务的未提交修改；阶段 0 以当前工作树和现有测试为基线，不重置或覆盖无关改动。

## 3. 页面结构

### 3.1 顶部栏

左侧显示：

```text
[狐狸头像] CodeFox  ·  当前会话标题
```

顶部栏右侧固定提供三个按钮；`[状态]` 是会话状态面板的入口，显示在对话区顶部行右侧（与“加载更早记录”同一行），窄屏时为标题行右侧，不占这三个按钮：

- 会话历史：打开保存会话列表，可恢复已有会话、删除非当前会话；当前会话的历史仍在对话区查看。
- 设置：打开只读运行信息，包括模型、启动目录、工作树、会话 ID、字符预算和当前状态。
- 开启新会话：提交本地命令 `/new`（由共享运行时执行“保存并创建新会话”）；有模型回合、审批、关闭流程或未结算后台事件时禁用，沿用第 6.3 节规则。按钮与输入框敲 `/new` 共用同一条提交路径，按钮不单独实现清理逻辑。

顶部采用紧凑比例：品牌栏 1 行高，三个按钮整体靠右排列，各 1 行高、自动适应文字宽度、左右内边距不超过 1 个终端单元格；按钮不设置大块固定宽度。宽屏收起状态时对话区占满主体，`[状态]` 入口停在对话区顶部行右侧；展开时按“对话区 1fr + 状态列 32 列”分配，底部输入区约 6 行高，避免顶部按钮挤压对话内容。

顶部入口只构造运行时请求或读取显示状态，不直接读写会话文件，也不绕过 `InteractiveRuntime`。
“会话历史”不新建数据源：只打开保存会话列表；当前会话历史始终在对话区，用“加载更早记录”查看；没有当前会话时显示空状态。

### 3.2 对话区

- 使用现有 `ConversationRecord`、`ProcessGroup`、`OperationEntry`、`StreamingText` 和 `ApprovalCard`。
- 每条完整的用户消息和模型消息都使用独立的小消息框包裹；同一条消息的换行仍在同一个框内，不按标点把一句话拆成多个记录框。
- 每条 Hook、工具调用、工具结果、后台事件、TODO、审批和回合摘要也使用独立的暗色事件框包裹；同一事件的详情可折叠在该事件框内。
- 同一模型调用产生的多条执行事件在外层再套一个框；现有 `ProcessGroup` 目前只显示 `{source} · 操作` 静态标题加独立滚动内容，本计划把它改为按第 3.2 节描述的行为。收起时只有一行 `运行中 <本次操作>`，操作按本次执行的实际内容原样透传（工具名加完整参数），不截断、不改写、不压缩成摘要，仅在行尾附“已耗时 Ns”，例如 `运行中 bash npm test · 已耗时 2s`；超长内容在框内换行，不省略。单击该行展开后，框内先显示一行 `已运行的命令` 作为分组头，再逐条列出 `已运行 <本次操作>`；框不写“操作组”之类标题。
- 在左侧对话区内部，模型回复固定在左侧，用户输入固定在右侧；两者正文使用同一组主文字颜色，不用颜色暗示谁更重要。
- 左侧对话区内的用户消息使用明确的右对齐布局约束（容器或消息块设置 `align-horizontal: right`），模型回复使用左对齐布局；只通过位置和消息块边界区分角色，消息框内不显示“CodeFox”“你”等来源标签或头像。这里的“右侧”指对话区内部，不是右侧的会话状态面板。验收必须比较消息组件的实际 `region.x`，不能只检查 CSS 类名。
- 工具调用/结果、Hook、TODO、后台事件、审批和回合摘要继续按展示记录显示，并各自包裹为低亮度暗色事件框放在对话流中，不伪装成用户或模型消息。
- 事件框统一左对齐，与模型回复框使用相同的起始边界；只有用户消息框右对齐。事件框可以占对话区较宽空间，但不进入会话状态面板。同一次调用的外框整体左对齐，只包裹该次调用的执行事件；用户消息、模型回复和 TODO、回合摘要、审批等不进入外框。外框收起时只显示正在进行的那一条 `运行中` 行，已结束的事件在展开后才以 `已运行` 行显示；同一时刻有多条进行中操作时按开始顺序显示最先一条，并在该行末尾标注“还有 N 条进行中”。
- 工具和 Hook 事件显示耗时：执行中按开始时间实时累计，结束、失败或停止后固定为本次已结束的总耗时；没有结束事件时不显示“完成”，只显示“进行中 · 已耗时 Ns”。单个事件行用“进行中”，调用外框收起汇总行用“运行中”，两者不混用。
- 耗时优先使用后端事件提供的开始/结束时间或已确认耗时；活动事件由前端单调时钟刷新，刷新和恢复依据记录中的时间重新计算，不能把已用时间清零。
- 历史记录默认展示最近窗口，保留“加载更早记录”。
- 当前流式输出仍先显示临时片段，正式消息确认后只保留一份正文；失败或停止的尝试继续标记为未采用。
- 恢复会话时只重放记录，不重新执行工具、审批或后台任务。

### 3.3 颜色与视觉层级

- 整体采用暗色背景：主背景沿用当前 `#151719`，对话区和输入区使用相邻的深灰表面，不使用大面积纯黑或高亮背景。
- 用户消息和模型回复的正文使用同一主文字色（浅灰/近白）；用户消息块可使用略亮的深灰表面，模型消息块使用略暗的深灰表面，差异保持克制。
- 事件按类型使用不同色相，但同属低饱和暗色系：Hook 用青灰、工具调用/结果用蓝灰、后台事件用紫灰、TODO 用绿灰、回合摘要用中性灰；正文亮度保持一致，详细参数默认折叠。
- 同一次调用的外框使用比内部事件框更暗的表面和细边框，不写标题；收起行以 `运行中 ` 开头、展开后每组以 `已运行的命令` 开头，各 `已运行` 行按操作类型着色。操作文本按本次执行的实际内容原样透传，不再使用现有 `arguments_summary` 的 110 字符截断。没有进行中操作时该框不显示。
- 用户消息和模型回复正文仍使用同一主文字色；用户消息框边框偏青、模型消息框边框偏灰蓝，只做轻微区分，不用颜色暗示谁更重要。
- 审批使用琥珀色边框或标签，成功使用低饱和绿色，失败使用低饱和红色，停止使用灰黄提示色；颜色同时配合文字标签，不能只靠颜色传达状态。
- 右上角三个按钮使用 CodeFox 青绿作为主色：`会话历史`为描边按钮、`设置`为中性描边按钮、`开启新会话`为青绿实心主按钮并带深色文字；禁用态统一降亮度，不用单独颜色表达职责。
- 会话状态面板使用比对话区更暗的表面和左侧分隔线；面板标题用青绿，字段名为中性灰、字段值用略亮的近白，状态值按状态复用审批/成功/失败/停止色。
- 各类方框统一“暗色表面 + 细边框”：主背景 `#151719`，对话表面 `#191b1d`，事件表面 `#17191b`，调用外框表面 `#141618`，输入区表面 `#202326`；边框颜色比各自表面亮一档，不出现纯黑或高饱和大色块。
- 保持普通终端和低色彩终端可读：所有状态至少有文字、符号或边框差异；颜色不可用时仍能区分用户、模型、事件、审批和错误。配色只用于加速区分，不承担唯一的信息表达。
- 不为每个事件设置高饱和荧光色，不使用渐变、闪烁或大面积彩色背景。
- 默认采用紧凑密度：正文使用终端原生小字号/单元格，不额外放大；消息框上下间距为 1 行以内，状态行和按钮高度为 1 行，减少空白区域。
- Textual 不能可靠控制终端的实际点字号，因此“字体小一点”落实为紧凑间距、短标签、较小内边距和不加粗正文；不新增字号设置假象。

### 3.4 会话状态面板

右侧会话状态面板显示运行状态，不把它命名为“上下文”。TUI 只消费运行时的只读展示投影，显示：

- 会话 ID 和会话状态：就绪、处理中、关闭中；停止请求不产生单独状态。
- 当前消息数量。
- 当前 goal：无目标、目标条件和已有状态。
- TODO：当前列表及状态。
- 工作目录、任务 ID 和工作树（存在时显示）。
- 活跃子 agent 名称与模式/状态。
- 主模型累计请求数、输入 token 和输出 token。

其中消息历史、goal、TODO、子 agent、模型、忙闲和用量直接来自现有 `state_snapshot`；工作目录、任务 ID 和工作树由运行时从当前会话状态一并投影。面板只读，TUI 不直接导入 `session_store` 或读取会话文件。左侧对话上下文的修改继续由用户输入、模型工具和 `/goal` 等已有命令完成。

### 3.5 底部输入区

- 输入框右侧只放一个主按钮，只有“发送”和“停止”两个文案：就绪时为“发送”，正在回复且有可停止回合时为“停止”；点击“停止”只发出停止请求，按钮随即禁用并保持“停止”，直到收到后端回合结束事件才恢复“发送”。
- Enter 直接发送，Shift+Enter 插入换行；这是对普通文本输入框的显式按键处理，不能依赖 Textual 默认的 Enter 行为。粘贴多行文本不触发发送。保留 Ctrl+Enter 作为已有发送快捷键，以及 Ctrl+L 清空、Ctrl+C 停止和 Ctrl+D 退出。
- 命令候选面板打开时，Enter 沿用现有命令选择/提交规则；Shift+Enter 始终只换行。审批卡和其他弹窗中的 Enter 沿用各自确认规则，不发送输入框草稿。
- 输入框上方显示当前处理状态或已有错误；状态区分就绪、处理中、关闭中，只来自 `state_snapshot` 的 `busy`/`closing`，请求停止后仍显示“处理中”，直到后端回合结束，前端不新增“停止中”状态。
- 输入框下方左侧显示权限摘要：`按工具策略`；发生审批时显示 `等待审批`，拒绝/停止沿用后端事件结果。
- 输入框下方右侧显示当前模型名、消息数量和字符预算 `core.CONTEXT_LIMIT`。
- 不显示可编辑的思考强度，不显示不存在的“Full access”状态。

## 6. 交互规则

### 6.1 会话历史与恢复

1. 用户点击顶部“会话历史”；当前有可停止回合、审批或关闭流程时入口禁用，沿用运行时忙碌规则。
2. TUI 提交 `/resume`，打开后端返回的会话列表。
3. 用户选中会话后提交 `/resume <id>`。
4. 后端完成当前会话保存、目标校验、工作目录切换和上下文激活后发送 `session_changed`。
5. TUI 清理旧显示状态，重放目标会话记录，刷新会话状态面板和标题。
6. 恢复失败时只显示后端错误，不改变当前页面上下文。

### 6.2 删除会话

- 面板只允许选择会话后调用 `/delete <id>`。
- 当前活动会话由后端拒绝删除；前端显示错误并保留当前对话上下文。
- 删除成功后重新请求会话列表，不清空当前对话，除非后端已有对应切换行为。

### 6.3 开启新会话

- 顶部“开启新会话”提交本地命令 `/new`，由后端先保存当前会话，再创建新的会话 ID、空消息历史和空展示记录。
- 新会话不继承旧会话的 Goal、TODO、活动任务、工作树绑定、审批、后台事件或草稿；旧会话文件保留，可从“会话历史”恢复。
- 当前有模型回合、审批、关闭流程或未结算后台事件时，按钮禁用；运行时拒绝时保留当前页面和草稿并显示错误。
- 前端收到新会话状态事件后，清理旧展示记录、标题和状态面板，再绑定新会话；不能只清空 UI 组件。

### 6.4 设置入口

- 设置面板只读显示当前模型、会话 ID、启动目录、工作树、字符预算、忙闲和用量。
- 没有对应后端字段的思考强度、模型切换、权限模式切换不显示为按钮或选择器。
- 设置面板不保存数据，不产生新会话事件。

### 6.5 权限展示

- 展示“按工具策略”这一事实性摘要。
- 工具需要确认时展示“等待审批”，审批卡仍使用现有 `ApprovalCard`。
- 拒绝、停止、关闭和 hook 错误继续以现有 `tool_result`/`execution_status` 显示。
- 前端不根据文字猜测权限，不把一次审批结果改写成全局权限模式。

### 6.6 发送、停止与换行

- 点击“发送”和输入框内按 Enter 共用现有提交入口；空白输入不发送，后端拒绝提交时保留草稿，仅接受成功后清空输入框。
- 回复期间仍可编辑下一条草稿；Enter 不停止当前回复，也不提交新回合，草稿保持原样。
- 点击“停止”或按 Ctrl+C 调用现有 `InteractiveRuntime.request_stop(turn_id)`，不清空草稿，不删除已保存的交互记录。
- “停止”是停止请求，不是立即终止。后端在模型循环边界和每次工具调用开始前检查停止标志：正在进行的模型流式读取会提前结束，已经开始的工具会执行完，尚未开始的工具调用跳过并标记为 `stopped`，等待中的审批按现有通道清理。
- 停止请求发出后禁用主按钮并保持“停止”，直到收到后端回合结束事件才恢复“发送”；不得点击后立即显示为已停止。正在执行的工具可能需要等待结束，沿用后端停止语义。
- 从发出停止请求到回合真正结束之间，运行时仍视为忙碌，提交新回合会被后端拒绝；输入框此时仍可编辑草稿，待回合结束后再发送。
- 等待审批时，有可停止回合就仍显示“停止”；停止后的审批清理沿用现有通道。
- 正在执行命令、尚未取得可停止回合 ID 或正在关闭时禁用主按钮；不把所有忙碌状态都视为可停止；关闭中禁用按钮且不改变按钮文案。
- Shift+Enter 的按键识别需在 WSL 实际终端验收；如终端将它与 Enter 发送为同一按键，明确报告该终端限制，不宣称换行快捷键已验证。

## 10. 风险与明确取舍

- Textual 对 SVG 的直接渲染能力可能受终端限制，因此 Logo 需要可验证的备用显示；不能因此引入图片转换依赖。
- `state_snapshot` 当前没有精确上下文 token 使用量；界面显示消息数量、已有累计用量和静态字符预算 `core.CONTEXT_LIMIT`，不把它们混称为实时 token 窗口占用。
- 当前后端没有思考强度概念。后续若要加入 `High/Medium/Low`，应先单独设计模型请求参数和会话恢复语义，再扩展前端。
- 权限摘要只能表达已有策略和审批状态，不能推断用户拥有全权限。
- 终端主题和颜色数量存在差异，因此颜色只负责层级提示；角色和状态必须同时由位置、标签、符号或边框表达。配色方案集中在第 3.3 节，实现时用一套共享常量，不在各控件里散落色值。
- 耗时显示依赖事件时间信息；缺少结束时间时只能显示前端观察到的累计耗时并保持“进行中”，恢复出来的历史记录没有结束事件时显示“上次中断”，不显示 0 秒完成耗时。
- 顶部按钮的职责固定为会话历史、设置和开启新会话；新增入口必须先有共享运行时能力，不能由前端清空组件冒充。
