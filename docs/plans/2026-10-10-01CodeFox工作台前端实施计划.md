# CodeFox 工作台局部交互展示修正实施计划

日期：2026-10-11。版本：v25。状态：待实施。

本计划只修正模型生命周期、工具批次和错误展示这组局部行为。工作台其他已经存在的界面和运行时能力保持当前实现，不借本次修改重做整体界面。

## 1. 范围边界

### 1.1 本次允许修改

- 同一次模型调用下的工具批次外框和工具行；
- 模型生命周期行在对话区的展示方式；
- 工具错误、模型/API 错误的展示位置；
- 模型/API 错误在诊断日志关闭时的系统错误卡；
- 防止同一错误同时伪装成助手消息和错误正文。

### 1.2 明确保留

以下内容不在本计划内，保持当前行为和布局：

- 顶部品牌栏、历史、会话状态、新会话和设置入口；
- 会话恢复、会话文件、工作目录、任务、工作树和后台任务；
- 输入框、发送/停止按钮、权限摘要、审批卡、TODO 和活动状态；
- Lead 收尾行的状态、耗时、工具数、审批数和模型用量统计；
- `turn_finished` 的事件结构、`summary` 字段和关闭流程；
- CLI 的其他输出、工具协议、权限策略、模型重试和主循环；
- 诊断日志开关本身，只改变诊断日志是否可见。

本计划中的“删除”只删除错误重复展示和模型生命周期详情控件，不删除上述运行时能力或统计数据。

## 2. 错误归属

### 2.1 工具错误

工具返回 `ToolResult(status="failed")` 时，错误只属于对应工具调用：

```text
工具调用 · 耗时 1.8s
  read_file · 成功 · 0.2s
  grep      · 失败 · 0.4s
    Error: pattern not found
  pytest    · 成功 · 1.2s
```

- 用户在工具行看到成功/失败、耗时和原始错误正文；
- 原始错误码、退出码和工具返回文本不改写；
- 同一工具结果继续作为配对的 `tool_result` 回填给模型；
- 模型可以据此重试、换工具或解释失败原因；
- 工具错误不进入模型回复文本区域；
- 普通工具失败不追加 `[Error]` 助手消息，不终止模型继续处理工具结果。

“回传模型”的意思是：UI 显示给用户的工具错误正文，同时被写入下一次模型请求的工具结果消息，模型能读取该正文；它不是把工具错误复制成模型回复。

### 2.2 模型/API 错误

模型没有返回可展示的助手文本且确实发生错误时，错误同时进入两个用户可见位置：

- 诊断日志：保留完整技术原因；
- 对话区回复位置：显示系统错误卡。

系统错误卡只在发生模型/API/运行时错误时挂载；没有错误时不显示。发生错误时，无论诊断日志开关是开还是关都显示错误卡。诊断开关只影响诊断日志折叠块，不影响已经发生的错误卡。

系统错误卡不使用 `assistant_message` 类型，不写入模型历史，不伪装成模型生成的文本。`LeadTurn.finish()` 不再为模型/API 异常追加 `[Error]` 助手消息；`TurnOutcome.reason` 继续提供给诊断日志、系统错误卡和现有 Lead 收尾状态。

### 2.3 错误不跨区域复制

- 工具返回错误：工具区域 + 下一次模型输入；
- 模型/API 请求错误：诊断日志 + 系统错误卡；
- Lead 收尾仍显示当前既有状态和统计，但不再拼接完整错误正文；
- 不因错误来源不同而修改其他工作台区域。

## 3. 工具批次展示

### 3.1 外层工具框

当前 `ProcessGroup` 按 `(turn_id, source, model_call_id)` 聚合同一次模型响应触发的工具调用。本次只调整其显示语义：

- 收起标题显示 `工具调用 · 已耗时 Ns` 或 `工具调用 · 耗时 Ns`；
- 外层只显示整批工具的墙钟耗时，不显示整批成功或失败；
- 总耗时从第一项工具开始到最后一项工具进入终态；并行执行取墙钟跨度，不累加子工具耗时；
- 外层不因为一个子工具失败而显示“失败”；
- 模型一次返回三个工具时，三个工具共用一个外框；模型下一次重新请求工具时创建新的外框；
- 没有工具调用的纯文本模型回复不创建工具框。

模型 API 在工具执行前失败时没有工具框。工具执行完后下一次模型请求失败时，也不把模型错误附加到上一批工具框；模型错误按第 2.2 节展示。

### 3.2 工具行

每个工具行显示：

```text
工具名 · 成功/失败/已拒绝/已停止 · 耗时
```

工具行的状态来自 `ToolResult.status` 和对应的 `execution_status`，不从正文猜测。失败正文在工具行显示短摘要，展开详情后显示完整参数和完整结果。

模型生命周期事件不再单独生成类似 `失败 · 耗时 0.0s` 的模型操作行。模型回复文本继续由现有流式正文和 `assistant_message` 控件显示。

## 4. `turn_finished` 只做现有回合收尾

本次不修改 `turn_finished` 的数据结构和统计字段。它继续作为运行控制事件完成当前已有职责：

1. 清除当前 `turn_id`；
2. 将 `busy` 和停止状态恢复为空闲；
3. 关闭当前审批等待；
4. 恢复发送按钮；
5. 让关闭流程等待回合结束后再发布 `runtime_closed`。

它仍可以产生当前已有的 Lead 收尾行，但该行不再重复显示完整错误正文。此次不删除 `turn_finished.summary`，不删除统计生成、校验或 CLI/TUI 的其他既有用途。

## 5. 实施任务

### A. 错误出口调整

涉及：

- `src/agent_harness/agents/lead_turn.py`
- `src/agent_harness/frontends/tui/app.py`
- `src/agent_harness/frontends/tui/conversation_view.py`

执行：

1. 删除 `LeadTurn.finish()` 追加 `[Error]` 助手消息的行为。
2. 保留 `TurnOutcome.reason`，模型/API 异常继续由现有主循环结算。
3. TUI 收到失败终态时，始终将原因写入诊断日志并挂载系统错误卡。
4. 系统错误卡不受 `diagnostics_visible` 控制，不写入 `assistant_message`。
5. 普通工具失败继续由工具结果路径处理，不挂载系统错误卡。
6. Lead 收尾保留现有状态和统计，只移除完整错误正文的重复渲染。

### B. 模型生命周期行调整

涉及：

- `src/agent_harness/frontends/tui/conversation_view.py`
- `src/agent_harness/frontends/tui/widgets.py`
- `src/agent_harness/frontends/conversation.py`

执行：

1. `execution_status` 的 `phase="model"` 不再挂载用户可见 `OperationEntry`。
2. 模型状态事件仍由投影用于流式正文确认、作废和恢复判断。
3. 模型操作不再显示“详情”控件。
4. `ProcessGroup` 只作为工具批次外框使用。

### C. 工具组和工具行调整

涉及：

- `src/agent_harness/frontends/tui/widgets.py`
- `src/agent_harness/frontends/tui/conversation_view.py`
- `src/agent_harness/frontends/tui/presentation.py`

执行：

1. 为 `ProcessGroup` 记录第一项开始时间、最后一项终态时间和墙钟耗时。
2. 外框标题只渲染工具批次和总耗时，不渲染整体成功/失败。
3. `OperationEntry` 的工具摘要加入该工具终态和耗时。
4. 工具失败正文在默认行显示短摘要，详情显示原始完整结果和参数。
5. 保持现有 `model_call_id` 分组规则和工具结果配对规则。
6. 保持工具结果进入下一次模型请求的现有路径，不新增第二套错误传递机制。

## 6. 验收与测试

新增或调整与本次行为直接相关的测试，不修改无关界面测试：

1. 纯文本模型响应不出现模型生命周期操作行或模型详情控件。
2. 一次模型响应包含三个工具时，三个工具在同一个外框；外框只有总耗时，子行分别显示状态和耗时。
3. 工具失败时，工具行显示原始错误正文，下一次模型请求包含同一工具结果；不产生助手 `[Error]` 消息。
4. 模型/API 失败时，诊断日志始终记录原因；诊断开关两种状态下，系统错误卡都可见；正常完成时没有错误卡。
5. Lead 收尾的状态和统计保持现有行为，但不再重复渲染完整错误正文。
6. `turn_finished` 仍能让 TUI 恢复发送按钮、清理停止状态和审批等待。
7. 现有会话、顶部入口、输入区、审批、TODO、后台任务、CLI 统计和其他工作台行为没有回归。

```bash

PYTHONPATH=src python scripts/debug_pass.py
```

完成条件：两条命令通过；离线测试覆盖纯文本回复、三工具批次、工具失败、模型/API 失败、诊断开关开/关、停止和关闭；差异只落在本计划列出的文件和行为范围内。
