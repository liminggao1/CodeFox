# CodeFox 工作台局部交互展示修正实施计划

日期：2026-10-12。版本：v28。状态：已实施；A–E 完成。

本计划只修正模型生命周期、工具批次和错误展示这组局部行为。工作台其他已经存在的界面和运行时能力保持当前实现，不借本次修改重做整体界面。

当前实施边界：

- A–C 已实施：错误出口与系统错误卡、模型生命周期行隐藏、工具批次和工具行展示；
- D–E 已实施：输入区四种状态、删除 TUI 对话区 Lead 收尾行、底部最近一次 API token 上下文占用展示，以及 token 口径的自动压缩。

## 1. 范围边界

### 1.1 本次允许修改

- 同一次模型调用下的工具批次外框和工具行；
- 模型生命周期行在对话区的展示方式；
- 工具错误、模型/API 错误的展示位置；
- 模型/API 错误在诊断日志关闭时的系统错误卡；
- 防止同一错误同时伪装成助手消息和错误正文。
- 输入区回合状态的精简展示；
- 对话区 Lead 收尾统计的展示位置；
- 底部上下文窗口占用摘要。
- 使用 API `input_tokens` 的上下文占用显示和压缩判断。

### 1.2 明确保留

以下内容不在本计划内，保持当前行为和布局：

- 顶部品牌栏、历史、会话状态、新会话和设置入口；
- 会话恢复、会话文件、工作目录、任务、工作树和后台任务；
- 输入框、发送/停止按钮、权限摘要、审批卡、TODO 和活动状态；
- Lead 收尾的后台统计、`turn_finished.summary` 和运行控制；TUI 对话区不保留 Lead 收尾展示行；
- `turn_finished` 的事件结构、`summary` 字段和关闭流程；
- CLI 的其他输出、工具协议、权限策略、模型重试和主循环顺序；主循环只在本计划列出的压缩计量处调整；
- 诊断日志开关本身，只改变诊断日志是否可见。

本计划中的“删除”只删除错误重复展示、模型生命周期详情控件和 TUI 对话区 Lead 收尾行，不删除上述运行时能力或统计数据。

## 2. 错误归属

### 2.1 工具错误

工具返回 `ToolResult(status="failed")` 时，错误只属于对应工具调用：

```text
工具调用 · 耗时 1.8s
  read_file · 成功 · 0.2s
  grep      · 失败 · 0.4s
    Error: pattern not found
  pytest    · 成功 · 1.2s
```

- 用户在工具行看到成功/失败、耗时和原始错误正文；
- 原始错误码、退出码和工具返回文本不改写；
- 同一工具结果继续作为配对的 `tool_result` 回填给模型；
- 模型可以据此重试、换工具或解释失败原因；
- 工具错误不进入模型回复文本区域；
- 普通工具失败不追加 `[Error]` 助手消息，不终止模型继续处理工具结果。

“回传模型”的意思是：UI 显示给用户的工具错误正文，同时被写入下一次模型请求的工具结果消息，模型能读取该正文；它不是把工具错误复制成模型回复。

### 2.2 模型/API 错误

模型没有返回可展示的助手文本且确实发生错误时，错误同时进入两个用户可见位置：

- 诊断日志：保留完整技术原因；
- 对话区回复位置：显示系统错误卡。

系统错误卡只在发生模型/API/运行时错误时挂载；没有错误时不显示。发生错误时，无论诊断日志开关是开还是关都显示错误卡。诊断开关只影响诊断日志折叠块，不影响已经发生的错误卡。

系统错误卡不使用 `assistant_message` 类型，不写入模型历史，不伪装成模型生成的文本。`LeadTurn.finish()` 不再为模型/API 异常追加 `[Error]` 助手消息；`TurnOutcome.reason` 继续提供给诊断日志和系统错误卡，输入区只显示“失败”状态，不显示完整错误正文。

### 2.3 错误不跨区域复制

- 工具返回错误：工具区域 + 下一次模型输入；
- 模型/API 请求错误：诊断日志 + 系统错误卡；
- Lead 收尾统计继续写入 `turn_finished.summary`，并以一条紧凑诊断日志记录；TUI 对话区不再重复渲染 Lead 收尾统计；
- 不因错误来源不同而修改其他工作台区域。

## 3. 工具批次展示

### 3.1 外层工具框

当前 `ProcessGroup` 按 `(turn_id, source, model_call_id)` 聚合同一次模型响应触发的工具调用。本次只调整其显示语义：

- 收起标题显示 `工具调用 · 已耗时 Ns` 或 `工具调用 · 耗时 Ns`；
- 外层只显示整批工具的墙钟耗时，不显示整批成功或失败；
- 总耗时从第一项工具开始到最后一项工具进入终态；并行执行取墙钟跨度，不累加子工具耗时；
- 外层不因为一个子工具失败而显示“失败”；
- 模型一次返回三个工具时，三个工具共用一个外框；模型下一次重新请求工具时创建新的外框；
- 没有工具调用的纯文本模型回复不创建工具框。

模型 API 在工具执行前失败时没有工具框。工具执行完后下一次模型请求失败时，也不把模型错误附加到上一批工具框；模型错误按第 2.2 节展示。

### 3.2 工具行

每个工具行显示：

```text
工具名 · 成功/失败/已拒绝/已停止 · 耗时
```

工具行的状态来自 `ToolResult.status` 和对应的 `execution_status`，不从正文猜测。失败正文在工具行显示短摘要，展开详情后显示完整参数和完整结果。

模型生命周期事件不再单独生成类似 `失败 · 耗时 0.0s` 的模型操作行。模型回复文本继续由现有流式正文和 `assistant_message` 控件显示。

## 4. `turn_finished` 只做现有回合收尾

本次不修改 `turn_finished` 的数据结构和统计字段。它继续作为运行控制事件完成当前已有职责：

1. 清除当前 `turn_id`；
2. 将 `busy` 和停止状态恢复为空闲；
3. 关闭当前审批等待；
4. 恢复发送按钮；
5. 让关闭流程等待回合结束后再发布 `runtime_closed`。

它仍生成当前已有的 `turn_finished.summary`，但 TUI 对话区不再把它渲染为 Lead 收尾行。回合统计改写为诊断日志中的一条紧凑记录；输入区保留终态状态文案。此次不删除统计生成、校验或 CLI 的其他既有用途。

## 4.1 TUI 状态和上下文窗口摘要

- 输入区只显示四种回合状态：`处理中`、`完成`、`失败`、`已停止`；`就绪`仅作为内部空闲状态，`关闭中`仅作为内部关闭状态，不在输入区显示；不在该位置显示“已保存”或“输出截断”等附加提示；
- 对话区删除 Lead 收尾展示行；Lead 的状态、耗时、工具数、审批数和模型用量统计以紧凑的一行写入诊断日志，格式可为：`[TURN] 完成 · 22.2s · 工具 0 · 审批 0 · 请求 1 · 输入 3.2k · 输出 54`；
- 会话状态面板继续保留消息数量，因为它属于会话概览；底部摘要删除“消息：N”和静态“字符预算”；
- 底部摘要保留模型名，并显示 `已使用上下文窗口：14k/50k（28%）`；分子使用最近一次模型请求返回的 API `input_tokens`，分母使用当前模型配置的最大上下文 token 数；
- 首次请求尚未返回用量时显示等待用量的占位文本；后续每次模型响应成功后更新为最近一次请求的实际 `input_tokens`，不使用回合累计值替代当前请求值；
- 上下文占用低于 80% 使用正常颜色，80% 至 99% 使用警告颜色，达到 100% 显示满载状态并阻止普通输入；界面不显示超过 100% 的状态。
- 以上调整 TUI 展示；会话状态面板的消息数量保持不变，底部不再显示字符预算。

## 4.2 API token 口径和上下文压缩

- API `input_tokens` 是模型实际收到的请求上下文计量单位，作为上下文占用显示和自动压缩阈值的唯一口径；不再用 JSON 字符数或固定字符/token 比例替代；
- 模型上下文上限作为当前会话的显式 token 配置，模型切换时同步使用对应上限，不再复用 `core.CONTEXT_LIMIT` 的字符语义；
- 压缩发生在模型请求之前，而本次请求的真实 `input_tokens` 只有响应后才可得，因此 provider 适配层增加统一的请求前 token 计数接口，使用与当前模型协议一致的计数能力；
- 自动压缩必须在发送请求前取得预估 token 数，按模型上下文上限的 80% 触发、70% 作为压缩目标；工具结果预算继续按同一 token 口径换算；
- 最近一次 API 返回的 `input_tokens` 用于校准和展示，不能拿 Lead 回合累计 `input_tokens` 代替单次请求上下文大小；
- 工具输出截断、落盘预览和 shell 输出上限仍属于输出存储限制，继续使用字符单位，不把它们混入上下文窗口百分比；
- provider 没有独立的请求前计数端点时，适配层使用包含 system、messages 和 tools 的 token 估算器；这仍按 token 单位判断，不回退到字符阈值。API 响应返回的真实 `input_tokens` 只用于底部展示和最近请求校准。

6. 保持工具结果进入下一次模型请求的现有路径，不新增第二套错误传递机制。

### D. 回合状态和上下文摘要调整

涉及：

- `src/agent_harness/frontends/tui/app.py`
- `src/agent_harness/frontends/tui/widgets.py`
- `src/agent_harness/frontends/tui/presentation.py`

2. 移除 TUI 对话区 Lead 收尾行，保留 `turn_finished.summary` 和回合结束控制。
3. 将回合状态、耗时、工具数、审批数和模型用量写成一条紧凑诊断日志。
4. 底部删除消息数量和静态字符预算，改为模型名加 `已使用上下文窗口：used/max（percent）`，数值来自最近一次 API `input_tokens` 和模型上下文上限。
5. 按 80% 和 100% 阈值渲染上下文占用颜色；会话状态面板消息数量保持不变。

### E. API token 计量和压缩调整

涉及：

- `src/agent_harness/providers/llm_client.py`
- `src/agent_harness/context/compaction.py`
- `src/agent_harness/core.py`
- `src/agent_harness/host.py`
- `src/agent_harness/agents/subagent_session.py`

执行：

1. 为 provider 适配层增加统一的请求前 token 计数接口，计数输入包含实际发送的 system、messages 和 tools。
2. 将自动压缩的触发、目标和工具结果预算改为模型上下文 token 上限的比例，不再调用字符估算作为压缩判断。
3. 保留 API 响应中的单次 `input_tokens`，分别用于底部上下文窗口显示、诊断记录和压缩计量校准；不把回合累计用量当作单次上下文大小。
4. 工具输出截断、落盘预览和 shell 输出上限继续使用字符限制，避免把输出存储策略与模型上下文策略混在一起。
5. provider 没有请求前计数端点时，使用适配层 token 估算器完成压缩判断，不把字符数当作上下文 token。

## 6. 验收与测试

新增或调整与本次行为直接相关的测试，不修改无关界面测试：

1. 纯文本模型响应不出现模型生命周期操作行或模型详情控件。
2. 一次模型响应包含三个工具时，三个工具在同一个外框；外框只有总耗时，子行分别显示状态和耗时。
3. 工具失败时，工具行显示原始错误正文，下一次模型请求包含同一工具结果；不产生助手 `[Error]` 消息。
4. 模型/API 失败时，诊断日志始终记录原因；诊断开关两种状态下，系统错误卡都可见；正常完成时没有错误卡。
5. TUI 对话区不出现 Lead 收尾行；回合统计仍在诊断日志中可见，`turn_finished.summary` 和运行控制不变。
6. `turn_finished` 仍能让 TUI 恢复发送按钮、清理停止状态和审批等待。
7. 输入区只出现四种约定状态；正常完成时显示“完成”，停止时显示“已停止”，失败时显示“失败”，空闲时不额外显示“就绪”。
8. 会话状态面板仍显示消息数量；底部显示 `已使用上下文窗口：used/max（percent）`，不再显示“消息：N”或字符预算。
9. 自动压缩的触发和目标使用请求前 token 计数；没有独立计数端点时使用适配层 token 估算器，不按字符阈值执行。
10. 工具输出截断和落盘预览仍按字符上限工作，不受上下文 token 计量改动影响。
11. 现有会话、顶部入口、输入区、审批、TODO、后台任务、CLI 统计和其他工作台行为没有回归。
