# CodeFox 工作台局部交互展示修正实施计划

日期：2026-10-12。版本：v26。状态：待实施。

本计划只修正模型生命周期、工具批次和错误展示这组局部行为。工作台其他已经存在的界面和运行时能力保持当前实现，不借本次修改重做整体界面。

## 1. 范围边界

### 1.1 本次允许修改

- 同一次模型调用下的工具批次外框和工具行；
- 模型生命周期行在对话区的展示方式；
- 工具错误、模型/API 错误的展示位置；
- 模型/API 错误在诊断日志关闭时的系统错误卡；
- 防止同一错误同时伪装成助手消息和错误正文。
- 输入区回合状态的精简展示；
- 对话区 Lead 收尾统计的展示位置；
- 底部上下文窗口占用摘要。

### 1.2 明确保留

以下内容不在本计划内，保持当前行为和布局：

- 顶部品牌栏、历史、会话状态、新会话和设置入口；
- 会话恢复、会话文件、工作目录、任务、工作树和后台任务；
- 输入框、发送/停止按钮、权限摘要、审批卡、TODO 和活动状态；
- Lead 收尾的后台统计、`turn_finished.summary` 和运行控制；TUI 对话区不保留 Lead 收尾展示行；
- `turn_finished` 的事件结构、`summary` 字段和关闭流程；
- CLI 的其他输出、工具协议、权限策略、模型重试和主循环；
- 诊断日志开关本身，只改变诊断日志是否可见。

本计划中的“删除”只删除错误重复展示、模型生命周期详情控件和 TUI 对话区 Lead 收尾行，不删除上述运行时能力或统计数据。

## 2. 错误归属

### 2.1 工具错误

工具返回 `ToolResult(status="failed")` 时，错误只属于对应工具调用：

```text
工具调用 · 耗时 1.8s
  read_file · 成功 · 0.2s
  grep      · 失败 · 0.4s
    Error: pattern not found
  pytest    · 成功 · 1.2s
```

- 用户在工具行看到成功/失败、耗时和原始错误正文；
- 原始错误码、退出码和工具返回文本不改写；
- 同一工具结果继续作为配对的 `tool_result` 回填给模型；
- 模型可以据此重试、换工具或解释失败原因；
- 工具错误不进入模型回复文本区域；
- 普通工具失败不追加 `[Error]` 助手消息，不终止模型继续处理工具结果。

“回传模型”的意思是：UI 显示给用户的工具错误正文，同时被写入下一次模型请求的工具结果消息，模型能读取该正文；它不是把工具错误复制成模型回复。

### 2.2 模型/API 错误

模型没有返回可展示的助手文本且确实发生错误时，错误同时进入两个用户可见位置：

- 诊断日志：保留完整技术原因；
- 对话区回复位置：显示系统错误卡。

系统错误卡只在发生模型/API/运行时错误时挂载；没有错误时不显示。发生错误时，无论诊断日志开关是开还是关都显示错误卡。诊断开关只影响诊断日志折叠块，不影响已经发生的错误卡。

系统错误卡不使用 `assistant_message` 类型，不写入模型历史，不伪装成模型生成的文本。`LeadTurn.finish()` 不再为模型/API 异常追加 `[Error]` 助手消息；`TurnOutcome.reason` 继续提供给诊断日志和系统错误卡，输入区只显示“失败”状态，不显示完整错误正文。

### 2.3 错误不跨区域复制

- 工具返回错误：工具区域 + 下一次模型输入；
- 模型/API 请求错误：诊断日志 + 系统错误卡；
- Lead 收尾统计继续写入 `turn_finished.summary`，并以一条紧凑诊断日志记录；TUI 对话区不再重复渲染 Lead 收尾统计；
- 不因错误来源不同而修改其他工作台区域。

## 3. 工具批次展示

### 3.1 外层工具框

当前 `ProcessGroup` 按 `(turn_id, source, model_call_id)` 聚合同一次模型响应触发的工具调用。本次只调整其显示语义：

- 收起标题显示 `工具调用 · 已耗时 Ns` 或 `工具调用 · 耗时 Ns`；
- 外层只显示整批工具的墙钟耗时，不显示整批成功或失败；
- 总耗时从第一项工具开始到最后一项工具进入终态；并行执行取墙钟跨度，不累加子工具耗时；
- 外层不因为一个子工具失败而显示“失败”；
- 模型一次返回三个工具时，三个工具共用一个外框；模型下一次重新请求工具时创建新的外框；
- 没有工具调用的纯文本模型回复不创建工具框。

模型 API 在工具执行前失败时没有工具框。工具执行完后下一次模型请求失败时，也不把模型错误附加到上一批工具框；模型错误按第 2.2 节展示。

### 3.2 工具行

每个工具行显示：

```text
工具名 · 成功/失败/已拒绝/已停止 · 耗时
```

工具行的状态来自 `ToolResult.status` 和对应的 `execution_status`，不从正文猜测。失败正文在工具行显示短摘要，展开详情后显示完整参数和完整结果。

模型生命周期事件不再单独生成类似 `失败 · 耗时 0.0s` 的模型操作行。模型回复文本继续由现有流式正文和 `assistant_message` 控件显示。

## 4. `turn_finished` 只做现有回合收尾

本次不修改 `turn_finished` 的数据结构和统计字段。它继续作为运行控制事件完成当前已有职责：

1. 清除当前 `turn_id`；
2. 将 `busy` 和停止状态恢复为空闲；
3. 关闭当前审批等待；
4. 恢复发送按钮；
5. 让关闭流程等待回合结束后再发布 `runtime_closed`。

它仍生成当前已有的 `turn_finished.summary`，但 TUI 对话区不再把它渲染为 Lead 收尾行。回合统计改写为诊断日志中的一条紧凑记录；输入区保留终态状态文案。此次不删除统计生成、校验或 CLI 的其他既有用途。

## 4.1 TUI 状态和上下文窗口摘要

- 输入区只保留少量回合状态：`就绪`、`处理中`、`关闭中`、`完成`、`失败`、`已停止`；不在该位置显示“已保存”或“输出截断”等附加提示；
- 对话区删除 Lead 收尾展示行；Lead 的状态、耗时、工具数、审批数和模型用量统计以紧凑的一行写入诊断日志，格式可为：`[TURN] 完成 · 22.2s · 工具 0 · 审批 0 · 请求 1 · 输入 3.2k · 输出 54`；
- 会话状态面板继续保留消息数量，因为它属于会话概览；底部摘要删除“消息：N”和静态“字符预算”；
- 底部摘要保留模型名，并显示 `上下文窗口：6.4%（3.2k/50k 字符）`；分子使用当前会话历史的字符估算值，分母使用 `core.CONTEXT_LIMIT`，两者统一按字符计量；
- 不使用模型 API 的 `input_tokens` 计算底部占用，因为它是 token 单位并包含不同的请求上下文；该指标仍可作为诊断日志中的模型用量统计；
- 上下文占用低于 80% 使用正常颜色，80% 至 100% 使用警告颜色，超过 100% 使用错误颜色；
- 以上只调整 TUI 展示，CLI、会话状态面板和上下文压缩运行逻辑保持当前行为。

## 6. 验收与测试

新增或调整与本次行为直接相关的测试，不修改无关界面测试：

1. 纯文本模型响应不出现模型生命周期操作行或模型详情控件。
2. 一次模型响应包含三个工具时，三个工具在同一个外框；外框只有总耗时，子行分别显示状态和耗时。
3. 工具失败时，工具行显示原始错误正文，下一次模型请求包含同一工具结果；不产生助手 `[Error]` 消息。
4. 模型/API 失败时，诊断日志始终记录原因；诊断开关两种状态下，系统错误卡都可见；正常完成时没有错误卡。
5. TUI 对话区不出现 Lead 收尾行；回合统计仍在诊断日志中可见，`turn_finished.summary` 和运行控制不变。
6. `turn_finished` 仍能让 TUI 恢复发送按钮、清理停止状态和审批等待。
7. 输入区只出现六种约定状态；正常完成时显示“完成”，停止时显示“已停止”，失败时显示“失败”。
8. 会话状态面板仍显示消息数量；底部显示 `上下文窗口：x%（yk/50k 字符）`，不再显示“消息：N”或静态“字符预算”。
9. 现有会话、顶部入口、输入区、审批、TODO、后台任务、CLI 统计和其他工作台行为没有回归。
