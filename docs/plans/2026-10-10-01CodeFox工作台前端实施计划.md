# CodeFox 工作台前端实施计划

日期：2026-10-10。版本：v8。状态：计划草案，待审查和执行批准。

本计划参考用户提供的会话式 Code Agent 界面和 MokioClaw TUI 截图，深化现有 Textual 前端。目标是让用户可以从一个工作台完成会话恢复、历史浏览、左侧对话上下文查看、右侧会话状态查看和交互输入，同时严格复用当前后端能力。

## 1. 目标与边界

### 1.1 目标

- 在顶部提供当前会话标题、会话恢复入口、历史记录入口和已有会话操作入口。
- 在中部保留当前对话和执行事件流，继续使用后端保存的展示记录恢复历史。
- 在底部提供输入框、发送/停止、当前模型、会话状态摘要和已有权限状态。
- 使用现有 `assets/logo/1F98A.svg` 的狐狸头像，品牌文字只显示 `CodeFox`；`< >` 或 `>_` 仅作为小装饰。
- 窄终端仍可完成输入、发送、停止、审批、恢复和退出。

### 1.2 不纳入本计划

- 不实现新的会话、工作目录、任务、TODO、审批或模型后端能力。
- 不加入思考强度选择。当前后端没有 thinking/effort 字段或设置接口，界面不伪造 `High` 等值。
- 不加入权限模式切换、全权限开关或权限配置页。现有权限规则仍由 `permission_hook`、工具注册器和审批通道决定。
- 不加入模型切换、API 配置、主题编辑、插件市场、Trace 开关或通用设置存储。当前后端没有对应的运行时设置协议。
- 不重做会话文件、展示记录、事件顺序、审批确认屏障、恢复目录和共享 `InteractiveRuntime`。
- 不下载外部图片或引入新的 Logo；只引用仓库已有 SVG。

## 2. 当前能力调查

| 用户看到的内容 | 当前后端事实 | 计划处理 |
| --- | --- | --- |
| 恢复会话 | `/resume` 可列出会话，`/resume <id>` 恢复上下文并切回原启动目录 | 做成顶部按钮和会话面板入口 |
| 删除会话 | `/delete <id>` 可删除非当前会话；当前会话仍由后端拒绝删除 | 面板保留删除动作，显示后端错误 |
| 历史交互 | `events` 中有消息、工具、TODO、后台、审批和回合摘要；TUI 已支持恢复重放和分段加载 | 调整为主要内容区的历史记录 |
| 会话状态 | `state_snapshot` 提供消息历史、goal、TODO、子 agent、模型、忙闲和主模型用量 | 做成可折叠的会话状态面板 |
| 模型 | `state_snapshot.model` 来自 `core.MODEL` | 只读显示当前模型名 |
| 思考强度 | 当前代码没有 thinking/effort 状态或配置入口 | 不显示选择控件；可在设置说明中标记“未配置”或直接省略 |
| 权限 | 工具策略、路径限制、shell/MCP 审批和停止规则由后端执行 | 只显示“按工具策略/需要时审批”等已有事实，不允许前端修改 |
| 工作目录 | 会话恢复后后端回到原启动目录，工具继续使用当前任务工作树 | 在会话状态面板只读显示当前目录/工作树 |
| 设置 | 当前只有环境变量和启动配置，没有交互设置协议 | 只提供只读运行信息，不做可编辑设置页 |

## 3. 页面结构

### 3.1 顶部栏

左侧显示：

```text
[狐狸头像] CodeFox  ·  当前会话标题
```

右侧提供已有能力的入口：

- 会话恢复：打开保存会话列表，选择后提交现有 `/resume <id>`。
- 历史：打开当前会话的历史交互记录。
- 更多：显示当前会话信息和已有删除操作；删除仍调用 `/delete <id>`。
- 设置：打开只读运行信息，包括模型、启动目录、工作树、会话 ID 和当前状态。
- 轻量图标使用 `<>` 或 `>_` 装饰，不增加长段品牌说明。

顶部入口只构造命令或读取显示状态，不直接读写会话文件，也不绕过 `InteractiveRuntime`。

### 3.2 对话区

- 使用现有 `ConversationRecord`、`ProcessGroup`、`OperationEntry`、`StreamingText` 和 `ApprovalCard`。
- 在左侧对话区内部，模型回复固定在左侧，用户输入固定在右侧；两者正文使用同一组主文字颜色，不用颜色暗示谁更重要。
- 左侧对话区内的用户消息使用右对齐的深色消息块，模型回复使用左对齐的深色消息块；只通过位置、头像/来源标签和消息块边界区分角色。这里的“右侧”指对话区内部，不是右侧的会话状态面板。
- 工具调用/结果、Hook、TODO、后台事件和回合摘要继续按展示记录显示，但作为低亮度事件行或事件块放在对话流中，不伪装成用户或模型消息。
- 工具和 Hook 事件显示耗时：执行中按开始时间实时累计，结束、失败或停止后固定为本次已结束的总耗时；没有结束事件时不显示“完成”，只显示“进行中 · 已耗时 Ns”。
- 耗时优先使用后端事件提供的开始/结束时间或已确认耗时；后端没有确认值时由前端以单调时钟计算展示，刷新和恢复不能把已用时间清零。
- 历史记录默认展示最近窗口，保留“加载更早记录”。
- 当前流式输出仍先显示临时片段，正式消息确认后只保留一份正文；失败或停止的尝试继续标记为未采用。
- 恢复会话时只重放记录，不重新执行工具、审批或后台任务。

### 3.3 颜色与视觉层级

- 整体采用暗色背景：主背景沿用当前 `#151719`，对话区和输入区使用相邻的深灰表面，不使用大面积纯黑或高亮背景。
- 用户消息和模型回复的正文使用同一主文字色（浅灰/近白）；用户消息块可使用略亮的深灰表面，模型消息块使用略暗的深灰表面，差异保持克制。
- Hook、后台事件、工具调用、工具结果、TODO 和回合摘要使用更暗的事件表面与较低亮度文字；事件名称可使用低饱和青灰色，详细参数默认折叠。
- 审批使用琥珀色边框或标签，成功使用低饱和绿色，失败使用低饱和红色，停止使用灰黄提示色；颜色同时配合文字标签，不能只靠颜色传达状态。
- 顶部品牌和当前会话标题可以使用 CodeFox 的青绿色点缀；Logo 和 `< >`/`>_` 装饰不抢过正文。
- 保持普通终端和低色彩终端可读：所有状态至少有文字、符号或边框差异；颜色不可用时仍能区分用户、模型、事件、审批和错误。
- 不为每个事件类型设置独立鲜艳颜色，不使用渐变、闪烁或大面积彩色背景。

### 3.4 会话状态面板

右侧会话状态面板显示运行状态，不把它命名为“上下文”。使用现有 `state_snapshot` 作为唯一数据来源，显示：

- 会话 ID和会话状态：就绪、处理中、停止中、关闭中。
- 当前消息数量，必要时显示上下文字符预算 `core.CONTEXT_LIMIT`；不得把它描述成精确 token 消耗。
- 当前 goal：无目标、目标条件和已有状态。
- TODO：当前列表及状态。
- 工作目录、任务 ID 和工作树（存在时显示）。
- 活跃子 agent 名称与模式/状态。
- 主模型累计请求数、输入 token 和输出 token。

面板只读。左侧对话上下文的修改继续由用户输入、模型工具和 `/goal` 等已有命令完成。

### 3.5 底部输入区

- 输入框右侧只放一个主按钮：就绪时为“发送”，正在回复且有可停止回合时为“停止”，请求停止后为禁用的“停止中”。
- Enter 直接发送，Shift+Enter 插入换行；粘贴多行文本不触发发送。保留 Ctrl+Enter 作为已有发送快捷键，以及 Ctrl+L 清空、Ctrl+C 停止和 Ctrl+D 退出。
- 命令候选面板打开时，Enter 沿用现有命令选择/提交规则；Shift+Enter 始终只换行。审批卡和其他弹窗中的 Enter 沿用各自确认规则，不发送输入框草稿。
- 输入框上方显示当前处理状态或已有错误。
- 输入框下方左侧显示权限摘要：`按工具策略`；发生审批时显示 `等待审批`，拒绝/停止沿用后端事件结果。
- 输入框下方右侧显示当前模型名和会话状态摘要。
- 不显示可编辑的思考强度，不显示不存在的“Full access”状态。

## 4. Logo 与静态资源

- 使用 [assets/logo/1F98A.svg](../../assets/logo/1F98A.svg) 作为狐狸头像来源。
- Textual 中优先使用终端可稳定显示的 SVG/Unicode 适配方式；如果当前 Textual 组件不能直接渲染 SVG，则使用已有 SVG 的简化终端字符表现，不新增图片下载或转换依赖。
- 品牌组件只负责头像、`CodeFox` 和小型 `< >`/`>_` 装饰。

## 5. 模块职责

| 模块 | 本计划职责 | 不承担 |
| --- | --- | --- |
| `frontends/tui/app.py` | 组装工作台布局、切换面板、焦点、尺寸适配和已有事件消费 | 执行模型、工具或会话文件读写 |
| `frontends/tui/widgets.py` | 品牌栏、会话面板、会话状态面板、输入栏、权限/模型状态条及现有记录组件 | 解释或修改后端业务状态 |
| `frontends/presentation.py` | 共用状态文案、模型/权限/会话状态摘要格式化 | 保存状态或读取全局业务对象 |
| `runtime/interactive_runtime.py` | 继续提供 `/resume`、`/delete`、快照和事件 | 为 UI 增加设置系统或思考强度协议 |
| `runtime/session_store.py` | 继续负责会话列表、校验、保存和删除 | 适配新旧文件格式 |
| `assets/logo/1F98A.svg` | 提供狐狸头像静态资源 | 运行时状态 |

依赖方向保持：TUI → `InteractiveRuntime`/展示事件；TUI 不反向导入 `host`、`session_store`、`tasks` 或工具处理器。

## 6. 交互规则

### 6.1 会话恢复

1. 用户点击顶部会话入口。
2. TUI 提交 `/resume`，打开后端返回的会话列表。
3. 用户选中会话后提交 `/resume <id>`。
4. 后端完成当前会话保存、目标校验、工作目录切换和上下文激活后发送 `session_changed`。
5. TUI 清理旧显示状态，重放目标会话记录，刷新会话状态面板和标题。
6. 恢复失败时只显示后端错误，不改变当前页面上下文。

### 6.2 删除会话

- 面板只允许选择会话后调用 `/delete <id>`。
- 当前活动会话由后端拒绝删除；前端显示错误并保留当前对话上下文。
- 删除成功后重新请求会话列表，不清空当前对话，除非后端已有对应切换行为。

### 6.3 设置入口

- 设置面板只读显示当前模型、会话 ID、启动目录、工作树、上下文预算、忙闲和用量。
- 没有对应后端字段的思考强度、模型切换、权限模式切换不显示为按钮或选择器。
- 设置面板不保存数据，不产生新会话事件。

### 6.4 权限展示

- 展示“按工具策略”这一事实性摘要。
- 工具需要确认时展示“等待审批”，审批卡仍使用现有 `ApprovalCard`。
- 拒绝、停止、关闭和 hook 错误继续以现有 `tool_result`/`execution_status` 显示。
- 前端不根据文字猜测权限，不把一次审批结果改写成全局权限模式。

### 6.5 发送、停止与换行

- 点击“发送”和输入框内按 Enter 共用现有提交入口；空白输入不发送，后端拒绝提交时保留草稿，仅接受成功后清空输入框。
- 回复期间仍可编辑下一条草稿；Enter 不停止当前回复，也不提交新回合，草稿保持原样。
- 点击“停止”或按 Ctrl+C 调用现有 `InteractiveRuntime.request_stop(turn_id)`，不清空草稿，不删除已保存的交互记录。
- 停止请求发出后禁用主按钮，等待后端回合结束事件，再恢复“发送”；不得点击后立即显示为已停止。正在执行的调用可能需要等待结束，沿用后端停止语义。
- 等待审批时，有可停止回合就仍显示“停止”；停止后的审批清理沿用现有通道。
- 正在执行命令、尚未取得可停止回合 ID 或正在关闭时禁用主按钮；不把所有忙碌状态都视为可停止。
- Shift+Enter 的按键识别需在 WSL 实际终端验收；如终端将它与 Enter 发送为同一按键，明确报告该终端限制，不宣称换行快捷键已验证。

## 10. 风险与明确取舍

- Textual 对 SVG 的直接渲染能力可能受终端限制，因此 Logo 需要可验证的备用显示；不能因此引入图片转换依赖。
- `state_snapshot` 当前没有精确上下文 token 使用量；界面显示消息数量、已有累计用量和静态上下文预算，不把它们混称为实时 token 窗口占用。
- 当前后端没有思考强度概念。后续若要加入 `High/Medium/Low`，应先单独设计模型请求参数和会话恢复语义，再扩展前端。
- 权限摘要只能表达已有策略和审批状态，不能推断用户拥有全权限。
- 终端主题和颜色数量存在差异，因此颜色只负责层级提示；角色和状态必须同时由位置、标签、符号或边框表达。
- 耗时显示依赖事件时间信息；缺少结束时间时只能显示前端观察到的累计耗时，并明确保持“进行中”状态。
