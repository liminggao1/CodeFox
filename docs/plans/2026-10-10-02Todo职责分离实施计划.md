# Todo 职责分离实施计划

状态：草案，待审核后执行

## 目标

明确 Todo 的职责边界：

- 模型负责根据用户请求提出 Todo，并通过 `todo_write` 更新计划；
- 运行时负责校验、保存、恢复和发布展示事件；
- 前端只消费 `todo_updated` 等事件并展示当前进度；
- `agent_loop` 只编排模型调用和工具结果，不主动干预 Todo 计划。

## 当前现状

当前实现已经具备主要链路：

1. `todo_write` 校验列表后替换 `tasks.CURRENT_TODOS`。
2. 更新成功后发布 `todo_updated` 事件并保存会话检查点。
3. 会话快照包含 Todo，恢复时重新加载。
4. `agent_loop` 使用全局 `rounds_since_todo` 统计工具调用，并在达到阈值后向模型追加提醒；这部分将删除。

仍需调整的边界：

- 删除与 Todo 提醒有关的计数器、阈值和内部消息；
- 将 Todo 状态管理限定在模型提交和运行时校验、保存、恢复、展示；
- 保留 `todo_write` 的单一写入入口，避免运行时自动猜测完成状态。

## 已确定的设计

### 模型与运行时的边界

模型拥有计划内容的决策权。运行时不根据工具结果自动猜测 Todo 状态，也不自动把 Todo 标记为完成。

运行时只保证：

- 输入格式正确；
- 状态可以持久化和恢复；
- 更新可以通知前端；
- 不根据工具调用次数催促模型更新计划。

### 是否提醒模型

本次不向模型追加 Todo 提醒消息，也不新增 `todo_reminder` 事件。模型是否创建或更新 Todo 完全由模型根据任务自行决定。

### 提示词范围

本次不新增长篇系统提示词，也不扩写 `todo_write` 工具描述。模型已经通过工具定义获得 Todo 能力；如果后续验证显示模型经常漏写 Todo，再单独增加最小规则。

## 实施步骤

### 1. 删除运行时提醒逻辑

涉及：`src/agent_harness/host.py`。

- 删除 `rounds_since_todo` 全局变量；
- 删除主循环中的 Todo 阈值判断、计数清零和提醒消息；
- 删除不再使用的 `TODO_REMINDER_ROUNDS` 配置；
- 不改变工具迭代、goal 判定、上下文压缩和模型重试顺序。

### 2. 保持 `todo_write` 为唯一写入入口

涉及：`src/agent_harness/tools/file_tools.py`、`src/agent_harness/workspace/tasks.py`。

- 保留现有输入校验和完整列表替换行为；
- 保留 `todo_updated` 事件和会话检查点；
- 不根据工具结果、文件状态或模型普通文本自动修改 Todo；
- 不新增 Todo 专用数据库或独立存储。

### 3. 保持会话和前端链路

不新增前端状态模型。继续使用现有 `todo_updated` 事件：

```text
todo_write
  -> CURRENT_TODOS
  -> todo_updated
  -> CLI/TUI 展示
```

前端展示的是模型提交的 Todo 状态。会话恢复继续恢复 Todo 内容，不需要恢复提醒计数。

## 测试与验收

新增或调整针对行为的测试，至少覆盖：

1. 普通工具调用不再生成 Todo 提醒消息。
2. `agent_loop` 不再读取或修改 Todo 计数器。
3. Todo 输入校验仍拒绝缺少字段和非法状态。
4. 成功 `todo_write` 仍发布 `todo_updated` 并保存检查点。
5. 失败 `todo_write` 不替换当前 Todo。
6. 恢复会话后 Todo 内容正常恢复。
7. 现有模型工具迭代、CLI/TUI 展示和离线自检不回归。

验证命令：

```text
python -m pytest -q
python scripts/debug_pass.py
```

完成标准：模型通过 `todo_write` 提出和更新计划；运行时可靠校验、保存和恢复；前端继续显示 Todo 更新；运行时不通过隐式提醒干预模型计划；`agent_loop` 不再持有 Todo 计数实现。

## 不在本次范围内

- 不新增 Todo 数据库存储；
- 不改变 Task、子 agent 任务、worktree 或 goal 的生命周期；
- 不引入新的第三方依赖；
- 不通过内部消息或 Hook 催促模型更新 Todo；
- 不添加长篇系统提示词规则。
