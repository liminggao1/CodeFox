# Todo 职责分离实施计划

状态：草案，待审核后执行

## 目标

明确 Todo 的职责边界：

- 模型负责根据用户请求提出 Todo，并通过 `todo_write` 更新计划；
- 运行时负责校验、保存、恢复、提醒和发布展示事件；
- 前端只消费 `todo_updated` 等事件并展示当前进度；
- `agent_loop` 只编排模型调用和工具结果，不直接管理 Todo 计数细节。

## 当前现状

当前实现已经具备主要链路：

1. `todo_write` 校验列表后替换 `tasks.CURRENT_TODOS`。
2. 更新成功后发布 `todo_updated` 事件并保存会话检查点。
3. 会话快照包含 Todo，恢复时重新加载。
4. `agent_loop` 使用全局 `rounds_since_todo` 统计工具调用，并在达到阈值后向模型追加提醒。

仍需调整的边界：

- 计数器位于 `host.py` 全局作用域，和主循环职责耦合；
- 当前按工具名称计数，不能区分工具成功和失败；
- `todo_write` 校验失败时也可能触发清零；
- 提醒阈值和提醒文本直接写在主循环中。

## 已确定的设计

### 模型与运行时的边界

模型拥有计划内容的决策权。运行时不根据工具结果自动猜测 Todo 状态，也不自动把 Todo 标记为完成。

运行时只保证：

- 输入格式正确；
- 状态可以持久化和恢复；
- 更新可以通知前端；
- 模型长时间执行工具时收到一次检查提醒。

### 提醒方式

继续把提醒作为下一次模型调用可见的内部消息写入当前回合。只发布 Hook 事件无法保证模型看到提醒，因此不新增单独的 `todo_reminder` 事件。

提醒阈值调整为 **5 次成功的普通工具调用**。计数只反映工具执行进度，不代表 Todo 已完成。

### 提示词范围

本次不新增长篇系统提示词，也不扩写 `todo_write` 工具描述。模型已经通过工具定义获得 Todo 能力；如果后续验证显示模型经常漏写 Todo，再单独增加最小规则。

## 实施步骤

### 1. 新增 Todo 进度跟踪器

建议位置：`src/agent_harness/runtime/todo_tracker.py`。

提供最小接口：

- `record_tool_result(name, success)`：记录一次工具结算；
- `record_todo_update(success)`：成功更新 Todo 时清零；
- `reminder()`：达到 5 次后返回一次提醒文本，否则返回 `None`；
- `reset()`：新会话或恢复会话时清零。

跟踪器不保存 Todo 内容，不写文件，也不发布前端事件。

### 2. 调整工具批次回调

涉及：`src/agent_harness/agents/lead_tools.py`、`src/agent_harness/host.py`。

- 将工具实际返回状态传给跟踪器；
- 只有成功完成的普通同步工具才增加计数；
- `todo_write` 只有成功校验并替换列表后才清零；
- 被停止、拒绝、未知工具和异常工具不增加计数；
- 保留现有工具结果、Hook、检查点和前端事件行为。

### 3. 收缩 `agent_loop` 的 Todo 代码

涉及：`src/agent_harness/host.py`。

- 删除 `rounds_since_todo` 全局变量；
- 删除主循环中的阈值常量判断和直接清零；
- 在准备下一次模型请求前调用跟踪器的 `reminder()`；
- 有提醒时继续追加内部模型消息；
- 不改变工具迭代、goal 判定、上下文压缩和模型重试顺序。

### 4. 接入会话生命周期

涉及：`src/agent_harness/runtime/interactive_runtime.py`。

- 运行时启动时创建当前会话的跟踪器；
- `/resume` 时重置跟踪器，不继承旧进程的临时计数；
- 关闭时释放引用；
- Todo 内容仍由现有会话快照保存和恢复。

### 5. 保持前端展示链路

不新增前端状态模型。继续使用现有 `todo_updated` 事件：

```text
todo_write
  -> CURRENT_TODOS
  -> todo_updated
  -> CLI/TUI 展示
```

前端展示的是模型提交的 Todo 状态，不展示运行时内部计数器。

## 测试与验收

新增或调整针对行为的测试，至少覆盖：

1. 成功普通工具调用累计计数。
2. 第 5 次成功普通工具调用后生成一次提醒。
3. 提醒生成后计数重置，不在每次模型调用重复提醒。
4. 工具失败、拒绝、停止和未知工具不累计计数。
5. 成功 `todo_write` 清零计数。
6. 失败 `todo_write` 不清零计数。
7. Todo 更新仍发布 `todo_updated` 并保存检查点。
8. 恢复会话后 Todo 内容恢复，但提醒计数从零开始。
9. 现有模型工具迭代、CLI/TUI 展示和离线自检不回归。

验证命令：

```text
python -m pytest -q
python scripts/debug_pass.py
```

完成标准：模型仍能通过 `todo_write` 提出和更新计划；运行时能可靠校验、保存、恢复和提醒；前端能继续显示 Todo 更新；`agent_loop` 不再持有 Todo 计数实现。

## 不在本次范围内

- 不自动根据文件是否存在推断 Todo 是否完成；
- 不新增 Todo 数据库存储；
- 不改变 Task、子 agent 任务、worktree 或 goal 的生命周期；
- 不引入新的第三方依赖；
- 不改用 Hook 替代模型可见的内部提醒消息；
- 不添加长篇系统提示词规则。
