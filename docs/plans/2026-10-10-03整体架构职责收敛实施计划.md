## 1. 问题与目标

| 候选 | 已核实的问题 | 目标与收益门 |
| --- | --- | --- |
| C1 对话展示状态 | TUI 主程序、控件和 CLI 分别维护片段确认、作废、身份关联和重放规则 | 共用语义集中；TUI 特有窗口规则由一个拥有者维护，两个 adapters 不再各写确认/作废规则 |
| C2 工具执行结果 | 结果正文、状态回调、生命周期分开传递；业务拒绝未必带错误前缀 | 工具在实际判断分支给出明确结果，Lead、child、后台消费同一契约；不从正文猜状态 |
| C3 Lead 会话状态 | Todo、会话 ID、保留工作树及保存回调混在任务板；多个模块直接写全局 | 运行时持有唯一 Lead 上下文对象，外部通过明确 interface 修改；保存读取不再修改归属 |
| C4 host 聚合入口 | 调用方经 host 访问工具、任务、调度和子 agent；真实拥有者被聚合导出遮蔽 | host 保留执行编排和启动装配，其他能力直接导入所属 module |

只移动文件、增加转发、把全局字段装进公开可写对象，都不满足收益门。
module 的 depth 通过调用方少懂规则体现；locality 通过一处修改和验证体现；leverage 通过真实调用方复用体现。
术语以 [GLOSSARY](../../GLOSSARY.md) 为准。

## 2. 已确认的行为与职责

1. C1 共用展示身份、片段去重、确认与作废；CLI 负责打印，TUI 负责挂载、分组、折叠、滚动和历史窗口。保留当前 CodeFox 布局和交互。
2. C2 工具在内部返回正文与明确执行状态。模型继续收到文本结果；失败由 Provider 按各自协议表达。
3. C3 运行时持有当前会话的 Todo、会话 ID 和工作目录关联；任务板继续负责任务文件、依赖、认领、assignment 及其版本。
4. C4 删除 host 聚合重导出，仓库内调用方、测试和调试脚本一起改用真实职责 module。
5. 工具已成功、PostToolUse 失败：先记录并保存真实工具结果，单独记录 Hook 失败，然后停止当前执行；不把工具改成失败，不重新执行它。
6. PreToolUse 抛异常：停止当前执行，handler 和 PostToolUse 不运行。明确拒绝和 Hook 实现异常继续区分。
7. 普通工具失败：生成配对的失败结果，同批其他普通工具按现有顺序继续；由下一次模型请求决定如何处理失败。
8. 部分操作后失败：整体请求为失败，正文列出已经发生的事实；保留资源和副作用，不自动重试或回滚。

“停止当前执行”指同步 Lead 的当前回合、child 的当前委派，或发生错误的后台任务。后台任务已经独立启动时，不因其 Hook 错误追溯停止已经结束的 Lead 回合，也不取消无关执行。
后台任务同时保留命令本身的结果和 Hook 错误；通知说明后置处理失败，不能声称命令没有执行。

02 计划原先保留 Error 字符串、tasks 状态和检查点，06 计划原先保留 host 聚合入口。本计划是用户确认的后续职责调整，实施后以本计划维护最新约束，旧计划保留当时实施记录。

## 3. 范围与不变量

- 沿用同步模型调用、单 Lead 执行线程、CLI 唯一输入线程及 Textual UI 线程；已有 workflow 并发机制保持原职责。
- 保留模型工具名称、输入 schema、权限范围、工具顺序、审批展示确认屏障和停止优先规则。
- Todo 仍由模型创建和更新；保留列表检查、整份替换、清单统计、空列表和完成清单。普通工具不自动更新 Todo，不注入提醒。
- 保留会话、任务、工作流 journal 的文件布局和必要字段。展示记录只写 JSON 数据，内部结果对象、异常和 UI 控件不写入会话文件。
- 延续失败保留 dirty、下次检查点重试保存的规则。无法保存时明确报告保存错误，不把尚未落盘的数据称为已持久化。
- 保留原有中文注释，随职责迁移更新；UTF-8 无 BOM、LF。
- 直接替换旧实现，不保留字符串/对象双入口、host 别名或兼容读取分支；依赖不增加。
- 不做界面改版、模型/配置全局重构、多运行时隔离、插件框架、工作流重写或通用事务与补偿系统。

## 5. C1：对话展示状态契约

建议 interface：`apply_record(record)`、`apply_delta(event)`、`restore(records)` 及只读条目读取。返回展示变更，不操纵控件或发布运行时事实。

- 记录按稳定 ID 去重；流式正文按会话、代次、回合、来源、模型调用和文本块关联，忽略已处理序号及过期片段。
- 接受正式 assistant_message 后，以正式正文确认片段。作废只影响同次未接受输出；确认后的正文不因其他尝试失败而作废。
- 工具按回合、来源、模型调用及工具调用 ID 关联；结果更新同一条目，不能错配其他回合。
- 实时和历史使用同一语义投影。历史中断标记继续由已有恢复准备提供，不运行模型、工具或审批动作。
- TUI view 独占控件映射、分组和窗口重建；控件不再另持有一份语义状态。展开状态、临时片段和当前审批在窗口重建时保留。
- 保留当前 80 条分段浏览策略、工具组内部滚动和跟随滚动规则；窗口截断不得显示半个工具组或丢失可操作审批。
- 确认屏障仍在 adapter 实际呈现完成后调用 acknowledge_event；投影成功不能代替展示成功。

## 6. C2：工具结果与失败结算契约

### 6.1 结果与协议

`ToolResult.content` 为结果正文，`status` 使用已存在的 `returned / success / failed / denied / stopped / started` 语义。
本地明确成功的操作标 success；外部处理器仅确认有返回且没有明确成功结论时可标 returned；后台派发标 started。
JSON 正文仍可作为字符串内容，但状态须来自生成它的原始结果，不反解析 JSON 或匹配文字猜状态。

- `failed / denied / stopped` 生成内部配对的 `tool_result.is_error=True`；success、returned 和 started 不标错误。
- Anthropic 路径使用已有内部工具结果字段。Responses 沿用当前 function_call_output 字段集，错误时由 Provider 将明确失败说明放入 output 文本，不发送臆造的错误字段。
- 工具输入协议解析、普通文本不执行、截断整批不执行的规则继续由现有 Provider 保证。
- 保留成功正文及有用错误正文；禁止为了表达状态把所有结果再包装成模型必须理解的新 JSON 格式。

### 6.2 在判断发生的位置给状态

| 来源 | 必须调整的实际判断与调用点 |
| --- | --- |
| 文件、Bash、Todo | `file_tools`、身份绑定和直接调用；Bash 保留退出码，成功正文包含 Error 字样仍成功；Todo 参数失败明确 failed |
| Task | `tasks` 的业务拒绝分支及 `shared_tools/registrations`；无法认领、完成或读取时给明确状态，不靠返回措辞判断 |
| 工作树 | `task_worktrees/worktrees` 的 Git 失败及部分操作；整体失败时列明资源已创建/已删除等事实 |
| 子 agent、通信与技能 | `subagent/subagent_protocol`、child 回调和 `context/skills` 的实际拒绝分支；spawn 状态从原字典取得 |
| MCP | 当前进程内模拟 client 及动态 handler；异常/未知工具明确 failed；任意正常正文不推断其业务含义 |
| Workflow | `run_workflow_sync` 工具 adapter 从 `WorkflowTool` 原始运行结果取得状态；runner、journal、预算和取消结算不重写 |
| compact | 保留请求接受与结果回填后压缩的时序；后续失败更新模型历史中原结果的正文和错误标记，发布同工具调用 ID 的结算更正事实并保存，不修改已经发布的事实或重跑其他工具 |
| 后台 Bash | 命令退出码与后置 Hook 错误分别保存；派发结果是 started，完成通知独立且只交付一次 |

普通领域查询仍可返回 Task、列表或原始 workflow 结果；只有实际工具 handler 返回 ToolResult。
同时供工具与内部调用的操作，在实际成功/拒绝分支给出结果，由工具 adapter 格式化正文；不得在 adapter 猜字符串，也不保留旧契约转发层。

### 6.3 Hook、记录与检查点顺序

1. 前置授权、PreToolUse 和停止检查按现有规则完成；拒绝不运行 handler 或 PostToolUse，停止优先于拒绝。
2. handler 执行一次，执行器取得明确结果；普通 handler 异常转换为 failed 工具结果。
3. PostToolUse 接收结果正文，按现有顺序运行一次；工具失败仍可进入后置记录，拒绝路径不进入。
4. 后置 Hook 异常保留原工具结果，并记录独立 Hook failed。执行器同时返回原结果和后置错误，内存异常对象只用于结束当前执行。
5. Lead/child 先追加或发布配对的真实工具结果，再结束当前执行。有检查点的执行调用检查点后才传播后置错误；独立 child 的检查点仍由运行时承担，发布的事实进入独立待保存队列，不能把入队称为立即落盘。保存失败保留待保存事实并报告，不丢掉已完成工具结果。
6. 中断批次的已结算工具结果可恢复；未执行项由既有恢复逻辑补中断结果，不再次执行已成功项。

后台不借 worker 写交互会话文件：先按已有目录保存真实输出，发布结果与 Hook 失败事实，由运行时检查点保存；该任务结束，后续通知明确后置处理失败。输出落盘失败时保留真实输出和待交付登记，沿用收集器重试保存，不重复执行命令或 Hook。前台或其他后台执行保持各自生命周期。
删除 `on_status`、`statuses` 列表与 `_last_tool_status` 旁路状态；结果结算只有一个 implementation。

## 7. C3：Lead 上下文拥有者契约

- `InteractiveRuntime` 显式创建 LeadContext，字段不对调用方开放任意写入；读取和更新均获得独立数据，Todo 参数对象不能在接受后反向修改状态。
- interface 收拢上下文读取、Todo 检查与替换、激活、工作树绑定/解绑。列表合法性检查保留一个实现；会话文件读取仍校验外部数据。
- 执行上下文传递当前 LeadContext 引用；直接离线主循环和调试入口显式创建并通过作用域提供它。没有交互通道的离线调用不因此创建展示通道或改走模型流式调用。子 agent 使用自己的 owner/assignment，不能修改 Lead Todo。
- tasks 获取 Lead 的 session_id、保留工作树关联时通过明确 interface。`assignments` 和 `assignment_versions` 继续由 tasks 持有。
- 首次会话创建和 `/resume` 激活时显式设置关联；保存仅读取。删除 `_session_context` 为保存先写 session_id 的隐含行为。
- 恢复准备只读验证原启动目录、任务和工作树；当前保存失败不激活目标。激活后保存失败保留目标及 dirty，沿用 04 的行为。
- 任务完成后释放 assignment，仍保留会话工作树；Git 移除目录成功后及时解绑。后续任务记录保存失败时仍如实保存已发生的目录变化，并返回部分操作失败。
- 启动目录继续由已有会话保存/激活流程维护，core.WORKDIR 由运行时切换；LeadContext 不再复制一份进程配置。
- Runtime 将现有 tasks.task_lock 显式提供给 LeadContext，任务分配与关联变更复用同一个 RLock，不增加互相等待的第二把状态锁。LeadContext 不导入 tasks 或 host；调用 checkpoint 在任务/状态锁释放后进行，不在读上下文时触发再次修改或保存。
- 运行时负责检查点。删除 `CURRENT_TODOS / lead_session_id / lead_worktree / save_lead_context` 全局及 `tasks.checkpoint_lead`；成功状态在工具结算和明确激活检查点保存，必须早于下一次模型请求。
- 关闭先等所属 child/后台结算并保存，再释放运行时上下文；没有运行时的调用明确提供必要状态，不创建隐含全局替代品。

## 8. C4：收窄 host interface

保留 host 自身的 `initialize_runtime / configure_goal / assemble_tool_pool / agent_loop` 及执行编排需要的内部函数。
保留当前 GOAL、显式初始化锁与 agent_lock 的实际用途，不把本次扩大成整个配置对象重构。

删除“Re-export names used by the CLI and source-level callers”聚合块；能力调用改为直接 import tasks、hooks、scheduler、subagent、file_tools、registrations 等拥有者。
仓库外的手写调试片段通过笔记更新调用方式，不增加旧别名。
Runtime 不再经 host.tasks/host.scheduler 等访问能力，测试 monkeypatch 指向被测实现实际读取的 module。
导入、重复初始化、失败后重试以及注入 runner 保留的行为由已有测试验收。
